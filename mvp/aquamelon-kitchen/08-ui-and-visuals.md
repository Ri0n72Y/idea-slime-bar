# 2D Lua UI 最小规格

## 1. P0 页面

**A 培养主屏：**上方标题与阶段；左侧土壤、Tree/Bud/至多三叶及其附属花果、真实 G 和合法下一目标；中间独立成熟材料/一键果汁；右侧随机元素球及操作；下方一行真实最近事件。

**B AI 品尝阅读层：**果汁来源、完整提示词、滚动或分页、返回；复制按钮只在实机证明可用时出现。

**C Debug：**独立入口，显示精确七元素值、Affinity、Reserve、物质账本、当前 uh、推进/Reset；普通界面绝不泄漏精确内部七维。

页面静态尺寸、位置、字号、按钮、图片由创作者在千星编辑器手动布置；Lua 只更新已绑定控件的文本、图片、显隐、状态，不自动调整布局。移动端需独立人工布局与实机确认。

## 2. 玩家操作与启闭

| 操作 | 合法条件 | 成功反馈 |
| --- | --- | --- |
| 放置土壤 | 空地块 | 显示已放土和种植入口 |
| 播种 | 已放土且无 Tree | Seed、G/45 出现 |
| 富集 | 土壤存在且该动作真实可用 | 生成一枚随机纯元素球；**不是 Debug 指定元素直供** |
| 收集球 | 当前绑定 `ballId` 存在 | 按真实剩余V加入 Soil，球列表刷新 |
| 清空球 | 尚有未收集球 | 只移除地面球，不回滚已入 Soil 的量 |
| 掐芽 | 活跃 Bud 且域允许 | 芽消失，Growth 回 Tree 后真实 G 刷新 |
| 采摘青果/叶 | 可采对象存在且域允许 | 生成有独立 ID 的对应地面材料；非 P0 主路径 |
| 采摘熟果 | 成熟果可采 | 移除活体果，新增 Aquamelon 材料 |
| 一键榨汁 | 一份真实 Aquamelon 材料 | 原材料消失，新增唯一果汁与完整账本 |
| AI 品尝提示词 | 选中真实果汁且数据齐全 | 生成冻结事实文本、打开阅读层 |
| 阅读翻页/返回 | 已生成提示词 | 保留同一份文本和来源 |
| Debug 快进/Reset | 调试页面 | 使用同一 Lua domain；Reset 清掉失效选中、速率采样记录 |

每个按钮的可用性最终由**领域操作 guard**判断；点击后必须依据真实结果反馈，不能先播成功动画再检查。

## 3. Growth 与信息显示

| 真实对象 | 普通玩家目标文本 | 账户重置规则 |
| --- | --- | --- |
| Seed | G/45 | 成为 Seedling 不清零 |
| Seedling | G/90 | 成为 Sapling 后换新 Tree Growth 账户 |
| Sapling | 本轮主干塑形 G/100 | 每100G重开周期，不是升级 |
| Bud | Bud G/20 | 新芽单独样本 |
| SmallLeaf | 本叶 G/26 | 升 LargeLeaf 本叶轴重置 |
| LargeLeaf | 本叶实际G，无已批准下一阈值就不画假分母 | 新阶段样本 |
| FlowerBud | 生殖G/12 | 后续始终同一生殖账户 |
| Flower | 生殖G/40 | 不清零 |
| GreenFruit | 生殖G/90 | 不清零 |
| MatureFruit | 已成熟/可采，实际 M 与生殖成熟里程碑分清 | 成熟 Stage 锁存，无升级分母 |

- **近期平均速率**：基于同一器官**自然生长新增的Growth事件量**，在最近完整`1uh`窗口内累计`ΔG_natural/1uh`；Seed、Bud、叶等无反应阶段可直接使用同一成长账户差值，采样不足显示「采样中」。
- **成熟果反应与速率分离**：果实`M = ΣE_free + ΣProducts`用于显示当前物质量；风扩散可改变M，普通反应改变自由/产物构成。这些均**不是自然Growth速度**，不能以成熟后窗口末M减窗口初M计算`G/uh`。可用领域已有的自然输入事件累计量作**只读统计**，不新增第二份可消费物质账本。
- **趋势**：连续两个完整1uh窗口才比较 ↑/↓/→；阶段重置后重新采样，不显示由阶段转换产生的负速度。
- **当前 Growth 状态**：每次真实结算后立即刷新合法阶段累计G或果实当前M，不因趋势采样不足停更；成熟后应把“自然富集速率”与“当前物质量M”分别标注。
- **普通模式**：可读总 G、阶段、定性元素倾向、合法下一目标；不暴露七维精确分量、Reserve、Affinity、内部预算、概率与模拟技术 Tick。
- **果实成熟后**：反应扣减可能改变 M；不要用反应后 M 倒推为未成熟，当前 M 不能代替首次成熟时的生殖累计 G。

## 4. 名称绑定建议

对象 `kind`（不是编辑器控件名）：`soil`、`seed`、`seedling`、`sapling`、`bud`、`small_leaf`、`large_leaf`、`flower_bud`、`flower`、`green_fruit`、`mature_aquamelon`、`aquamelon_juice`。

按钮操作键：`PlaceSoil`、`PlantSeed`、`CondenseBall`、`CollectBall`、`ClearBalls`、`PinchBud`、`HarvestFruit`、`MakeJuice`、`ShowTaste`、`PagePrev`、`PageNext`、`Reset`。

建议控件命名前缀 `WK_C_`，例如 `WK_C_TreeStage`、`WK_C_TreeG`、`WK_C_TreeRate`、`WK_C_Leaf01`、`WK_C_Repro01`、`WK_C_BallSlot01_Icon`、`WK_C_MaterialSlot01`、`WK_C_PromptText`、`WK_C_DebugPanel`。

图标对象键：除上方对象名外，七元素 `Fire/Hydro/Anemo/Electro/Dendro/Cryo/Geo`；P1 预留 `tool_inspect`、`tool_harvest`，P0 不必创建不可用的工具控件。

**首产物图标/名称的稳定数据键**：`vaporize_fire_to_hydro`、`vaporize_hydro_to_fire`、`melt_fire_to_cryo`、`melt_cryo_to_fire`、`overload`、`superconduct`、`freeze`、`electro_charged`、`burning`、`crystallize_hydro`、`crystallize_fire`、`crystallize_electro`、`crystallize_cryo`、`bloom`、`hyperbloom`、`burgeon`、`quicken`、`aggravate`、`spread`。这些是**UI资源和文本占位键**，不是新产物公式；按首个`Products`的实际类型和方向选取键。没有对应美术时统一使用占位图片与该键的可读中文名，P0不必为每种反应提交PNG。

固定槽位（如 `BallSlot01..04`、`MaterialSlot01..04`）只是可视容器，真实对象按 `ballId/materialId` 绑定；翻页或对象删除时更新绑定，不把“第3槽”永远等于“第3材料”。

## 5. 七元素主体色与图片文件名

| 元素 | 图标资产名（由编辑器导入） | HEX |
| --- | --- | --- |
| 火 | `Fire.png` | `#D56C45` |
| 水 | `Hydro.png` | `#4389CB` |
| 风 | `Anemo.png` | `#339F84` |
| 雷 | `Electro.png` | `#8742CE` |
| 草 | `Dendro.png` | `#8EAF43` |
| 冰 | `Cryo.png` | `#68B8BF` |
| 岩 | `Geo.png` | `#C2A045` |

表中 HEX 为七元素图标中提取的主体色。图片资产由创作者导入千星编辑器；Lua 使用编辑器注册的资源 ID，不直接使用文件路径。

**Lua 负责所有运行时显色：**编辑器只准备图标和控件，Lua 读取游戏内向量并按下述权重混合 RGB 后设置可写的图片色/颜色；不要运行时更改创作者布局。

**未形成反应产物：**

1. 取对象出生或当前阶段固化的 `BaseAffinity[7]`，每项除以其七维总和得到 `a[i]`；初始底色为 `C_base=Σa[i]×ElementRGB[i]`。
2. 取此对象当前真实的七维 `Growth[7]`（花果生殖期使用当前 `E_free[7]`），非零时归一为 `g[i]=Growth[i]/ΣGrowth`，获得 `C_growth=Σg[i]×ElementRGB[i]`。
3. 最终显示色 `C=0.70×C_base+0.30×C_growth`；若七维 Growth 总和为0，则仅显示 `C_base`。
4. **任何正量元素都直接参与混色**，不做主元素判定或额外显色阈值；元素成长时按新的权重刷新。

**反应产物出现之后：**

1. **第一次实际产生反应产物时**，用该产物的名称/图标锁定**整颗果子**的视觉身份；后续任何其他反应不再改变该图标和名称。锁定按真实结算事件顺序，而非产物数量大小、最终排序或预设优先类型。
2. 用除已生成反应产物之外的当前自由元素 `E_free[7]` 归一得到剩余元素 RGB 混合色。
3. 在反应产物专属图标基底上叠加 `30%` 的剩余自由元素混合色；没有剩余自由元素则不叠色。
4. **多产物不做混合命名/轮换图标**：第一个实际生成的产物决定唯一外形；其他产物只参与真实账本及品尝。首次产物后续即使被进阶消耗为0，视觉身份仍不改变，直到该果实离开场景。
5. **风扩散不会创建 `Products[Swirl]`**，因此单纯扩散不触发“首个产物”锁形；若同一事件中扩散之后首次产生了稳定/中间产物，按实际顺序锁形。首次反应产物身份只需一个最小的只读外形标记，不另存第二套物质量账本。

`C` 为三个 RGB 通道的线性加权混色；数值在 `0..255` 范围内裁剪/转换后传给编辑器有效颜色 API。这是**视觉数值**，不等于游戏资源增减，颜色混合不会消费 `Growth` 或 `E_free`。

图标注册仍用七元素固定名称，客户端图片替换必须使用编辑器导入得到的资源 `imageSource + imageId`；不能把文件路径直接当作有效图片 ID。普通界面继续隐藏精确七维数据，AI 品尝提示词才披露完整事实。

## 6. P1 单独延期

- 以像素画替换同名显示对象，不能改变其真实世界身份。
- 放大镜选择对象后在底部显示**定性**状态；普通工具不公开 Debug 数值。
- 手套选择可收获对象调用现有收获动作；不可摘时给真实失败反馈。
- P0 的最近事件小提示不是 P1 的“放大镜状态栏”。
