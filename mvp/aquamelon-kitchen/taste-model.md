# 水瓜厨房：三阶段 Taste 与感官描述设计共识

> **状态：已确认的概念与数据含义，2026-10-09；尚未批准转换公式、运行时字段或具体实现。**
>
> 适用于 Aquamelon Kitchen 的共同**数值/概念设计**。千星奇域与 Web 实现独立，不能因本文直接修改两端的领域计算或编辑器节点图。

## 1. 为什么重构

历史六维 Taste 同时包含基础味觉（甜、酸、苦）、口腔感官（涩、刺激）及综合印象（清爽），概念层级混杂。现在统一使用：

- **Taste：五种基本味觉**，独立定量。
- **Oral Sensation：四种口腔感官**，独立定量。
- **Feature Tags：非必需的特色标签**，补充香气、质地、风味转折及整体印象。
- 将以上描述沿**入口、中段、回味**三个阶段组织，不再采用此前讨论过的双极轴。

本设计追求可比较的风味描述，不把“强度”误当成“美味度”。

## 2. 三阶段

| 阶段 | 英文标记 | 关注的问题 |
| --- | --- | --- |
| **入口** | Entry | 最初接触时出现哪些味道、感官强度如何 |
| **中段** | Body | 含入口中或咀嚼时，主体味道和感官如何展开、并存或变化 |
| **回味** | Finish | 吞咽/结束品尝之后，留下哪些味道和感官、强度如何 |

“入口—中段—回味”是游戏采用的**离散描述阶段**，不是声称吞咽一定造成独立的新味觉，也不要求模拟真实时间曲线。此前单列的“吞咽”“后味”不再作为独立量化阶段；有必要时由标签或文字描述补充。

## 3. Taste：五种基本味觉

每个阶段分别记录五种味觉，数值范围暂定 **0～5**，均为独立的非负强度，不要求总和固定，也不视为质量/喜好评分。

| 中文 | 英文 | 含义 |
| --- | --- | --- |
| 甜 | Sweet | 甜味强度 |
| 酸 | Sour | 酸味强度 |
| 苦 | Bitter | 苦味强度 |
| 咸 | Salty | 咸味强度 |
| 鲜 | Umami | 鲜味（非“清新/清爽”）强度 |

甜与苦不是同一条正负轴；甜与苦可同时显著存在。咸与鲜作为旧六维 Taste 未包含的两种基本味觉纳入。

**量表的精度/步长、每一档的具体参照物尚未确认**；0～5 先定义强度区间，不强制整数。

## 4. Oral Sensation：四种独立口腔感官

每个阶段记录四项 **0～1** 的连续非负强度；0 表示无或不可感知，1 表示该感官在本模型中的显著强度，不是布尔开关。

| 中文 | 建议英文标记 | 含义 |
| --- | --- | --- |
| 涩 | Astringency | 收敛、干涩的口腔感觉 |
| 辣 | Pungency | 辛辣、灼热的口腔刺激 |
| 麻 | Tingling | 麻刺、针刺样或电麻感 |
| 凉 | Cooling | 清凉或化学性冷感 |

- **四项相互独立**，可同时大于零，不互相抵消。
- 不采用“涩—滑”“厚重—清爽”“清凉—热感”等双极轴；滑、厚重、清爽、绵密等如有必要可用**特色标签/描述**。
- “辣”在此为感官维度，不预先规定来源必须是辣椒；“凉”也不要求食物的物理温度降低。
- 涩涉及口腔收敛及摩擦等体验，属于本系统的口腔感官而不是第六种基本味觉。
- 旧版单一 `Tingle` 不能直接复用为新字段：现已明确拆分辣、麻、凉等方向；旧版 `Fresh`（清爽）也**不得**冒充 Umami（鲜）。

**量表精度、综合刺激解释与后续转换函数仍待定**，不能根据以上术语自动补齐公式。

## 5. Feature Tags：可选的特色标签

标签为三阶段数值难以充分表达的性质提供补充，可以描述：

- **动态与余韵**：回甘、生津、先苦后甜、余韵悠长、协调融合。
- **香气**：草本香、花果香、焙烤香、矿物气息。
- **质地**：顺滑、绵密、脆爽、凝胶、胶核、爆浆、气泡。
- **反应特征**：例如已有水草绽放讨论中的草种子状组织。

标签**不自动成为第十种量化维度**，既可以关联某个阶段，也可以关联整份料理；具体固定词表、存储方式、语义权重及自动生成规则尚未设计。回甘不增加一项“回甘 Taste”，也不能仅靠入口苦/回味甜就自动判定发生回甘。

“融合更好”与“更好喝”不是同一个概念：前者可成为风味描述标签，后者需要结合品评者偏好评价。

## 6. 三阶段统一感官模型（语义合同）

每个阶段各有：

```text
Taste[5]       : Sweet / Sour / Bitter / Salty / Umami     (0..5)
OralSensation[4]: Astringency / Pungency / Tingling / Cooling (0..1)
```

因此，一份完整描述有 **3 × (5 + 4) = 27 个可量化强度**，外加可选的 Feature Tags 与最终综合风味文本。各阶段维度一致，阶段之间的变化本身可以用于描述“先酸后甜”“后段微麻”等。

这只是一份**设计层字段语义**，不是要求在千星奇域编辑器中建立 27 个新变量，也不是确定客户端/服务端存储结构，更不要求现在就持久化这些派生数据。

## 7. 从七元素到风味评价：保持分层

### 现有权威事实（不变）

现行 [growth-system.md](growth-system.md) 仍规定：

```text
FruitElementAmount[7] = 结果后累计的七元素事实
FlavorRatio[e] = FruitElementAmount[e] / sum(FruitElementAmount)
```

`FlavorRatio` 目前仅代表**七元素组成比例**，不等于五味强度、口腔感官强度或品评得分。零总量、不重复持久化及成熟后继续富集等现行约束全部保持。

### 后续可设计的派生层（未实现）

```text
材料状态、七元素组成、加工与反应结果
→ 三阶段 Taste + Oral Sensation + 可选 Feature Tags
→ 综合风味描述
→ 按品评者偏好给出评价
```

- **AI 评价版**：综合风味描述、标签与顾客/玩家的喜好和厌恶等偏好交由 AI 作主观品评。AI 不负责修改已确定的元素事实或料理材料结果。
- **千星奇域无 AI 版**：仅用三阶段可量化强度做确定性的偏好匹配；初期不要求对标签作综合评分。具体相似度、权重、分数规则**尚未确定**。
- 两端**只共享数值与概念设计**，实现、数据组织、运行时权限和验收独立。千星奇域权威状态仍由服务端节点图负责。

## 8. 本次确认与明确未确认的范围

**已确认：**

1. 三阶段固定为入口（Entry）、中段（Body）、回味（Finish）。
2. 五种基本味觉：甜、酸、苦、咸、鲜，各阶段独立量化 0～5。
3. 四种口腔感官：涩、辣、麻、凉，各阶段独立量化 0～1。
4. 不采用双极轴；特色标签可选，补充香气、质地、回甘及复杂风味。
5. AI 评价与千星规则匹配共用感官语义，但实现独立。

**尚未确认，不得由实现者自行补齐：**

- 七元素 `FlavorRatio` 转为三阶段感官强度的算法和参数。
- Taste/Oral Sensation 的采样精度、取整或量化标尺、上限以外的行为。
- 加工与元素反应怎样产生标签、各标签如何影响 AI 或规则评价。
- 具体的规则匹配公式、顾客口味偏好数值、AI 输入格式、评估一致性方法。
- 是否需要额外的质地数值、嗅觉数值或更复杂的动态模型。
