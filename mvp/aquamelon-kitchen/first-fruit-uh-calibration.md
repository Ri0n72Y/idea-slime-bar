# 水瓜厨房：首果与浇水频率的统一期望值校准（2026-10-13）

> **本轮采用的设计校准基线：Tree Reserve 生长预算采用无休眠、0～180 V 归一化的平滑 S 曲线，中心 M=95 V、宽度 W=12 V。** 土壤蒸发 1%/uh；根系共享总吞吐采用 K=200 V 的对数曲线。此处是数值设计与确定性期望推演，不是已经部署的 Web / 千星奇域运行代码。原先 0.998/uh 蒸发、按每元素土壤浓度单独计算吸收效率、Reserve 100 V 满速平台与30/80 V休眠迟滞均不属于**本轮采用的基线**。详情与原始对照见本文数据表。

## 1. 玩家体验目标与当前验收差异

统一时间单位 [uh](../../docs/plants/uh-time-unit.md)：千星1uh=现实1小时，Web默认1uh=现实10秒，模拟固定步长1uh。玩家在 t=0 播种、浇水至 Soil 总量1000 V；此后周期性浇水以补充元素，使 Soil 总量回到1000 V。三类玩家使用**同一套参数与结算方法**，唯一差异是浇水的时间（24/48/72/168uh）。表中整日节点为当次浇水**前**的状态，168uh周玩家为第一次回访浇水前。

| 目标 | 当前期望轨迹 | 结论 |
| --- | --- | --- |
| 每天浇水，第24uh见Seedling、第48uh见SmallLeaf、第72uh见Flower | 事件仍由Growth阈值决定 | 体验目标不变 |
| 每天浇水，第96uh首次采摘 | 首果 **98uh** | 晚2uh，**尚未完全达标** |
| 隔天浇水尽量接近每日玩家 | 首果 **103uh** | 比每日晚5uh，不视为全程满速 |
| 每周浇水，第168uh有且仅有一颗成熟果，末期生长接近停滞 | 首果 **138uh**、168uh一颗、实际预算0.420V/uh | 单果与低速满足；并非恰在168uh成熟 |
| 每周玩家第二片叶刚形成/仍为SmallLeaf | 第二叶104uh出现；168uh为 **LargeLeaf** | **尚未达标** |

不通过“在第96或168uh自动成熟”、玩家类型加速、专属生长率或硬性每周产量上限实现目标。也不为命中单个时间点而把 S 曲线的过渡宽度压到2 V。

## 2. 确认的生命周期与预算语义（保持不变）

- Seed/Seedling都没有Reserve，共享连续TreeGrowth[7]，总量45G为Seedling、90G为Sapling；进入Sapling时各元素严格**1G→1V TreeReserve**，Sapling自身TreeGrowth清零，第一枚Bud同步产生。
- Bud20G→SmallLeaf；SmallLeaf自身26G→LargeLeaf并**同步产生FlowerBud**，只重置母叶自身阶段Growth，新生殖Growth独立从0开始。
- 同一生殖Growth[7]连续累计达到12/40/90G，分别为Flower/GreenFruit/Mature Aquamelon；花、果亲和各固化一次，但不重置生殖Growth；GreenFruit以后另记FruitElementAmount。
- Tree每片Leaf取当次预算30%，FlowerBud/Flower/GreenFruit统一取各自母叶所得份额的80%（单叶情况下为Tree预算24%）；成熟后20%富集仍是候选。七元素亲和>1允许放大实际Growth预算，不额外归一化。
- 后续Bud在本次试算中使用**确定性平均等待时间代理**，不是对随机出芽分布的严格数学期望，更不能作为玩家必得第二片叶的时间保证；实际出芽机会频率仍须另行确认。

## 3. Soil → 根系：1%蒸发、唯一共享的对数系数

七元素总库存 `S=ΣSoil[i]`，容量1000 V。每步先依结算规则自然蒸发，保留率为 `0.99 ** Δuh`；玩家每次浇水补充元素至1000 V。初始元素以七元素各1/7的**确定性期望分布**代替随机元素球，单球期望80 V，仅用于折算维护劳动量。

整株根系只计算**一个**共享土壤效率系数：

```text
F_soil(S) = ln(1 + S / 200) / ln(1 + 1000 / 200),  0 ≤ S ≤ 1000
```

各元素另受真实 `Soil[i]`、RootPreference、Tree Affinity和**各自单通道吸收上限**约束，不为每种元素另设一条浓度效率曲线。全部通道候选吸收量的合计受 `StageRootCap × F_soil(S) × Δuh` 约束；若合计超过共享上限，则同比缩减所有通道。RootPreference按Fire/Hydro/Anemo/Electro/Dendro/Cryo/Geo排列：`[0.8,1,0.85,0.75,1,0.7,0.9]`。试算根系阶段上限Seed/Seedling/Sapling为**2 / 1.85 / 16 V/uh**，单通道基础系数为`0.30×Tree BaseAffinity[i]`；Sapling的Reserve达到100V以上时，根系本身仍采用原有100～180V的ln充盈限制，满180V时吸收停止。**Reserve的30/80V休眠机制已移除**，不再根据活动状态停发Growth Budget。

## 4. Tree Reserve → Growth Budget：宽 S 曲线

`R=ΣTreeReserve[i]`，容量180 V；无30V下限，无Dormant/Growing迟滞。定义：

```text
sig(x) = 1 / (1 + exp(-x))
g(R)   = sig((R-M)/W)
F_growth(R) = clamp((g(R)-g(0))/(g(180)-g(0)), 0, 1)
M = 95 V; W = 12 V; 0 ≤ R ≤ 180 V
```

由当前真实 `Reserve[i]` 的构成派生各元素生长预算，并施加本元素Tree EffectiveAffinity，允许Affinity>1放大预算，但该元素本步实际提取不得超过Reserve[i]；本轮基准速率 `B0=5.4 V/uh`。归一化使`R=0 → 0%`、`R=180 → 100%`；`M=95`只表示效率中点，不是新的休眠阈值。**Budget随Reserve连续变化，绝不根据浇水频率直接更换曲线。**

| R（V） | 本轮S曲线的理论预算系数（约） |
| ---: | ---: |
| 180 | 100% |
| 150 | 98.9% |
| 120 | 89.0% |
| 110 | 77.8% |
| 100 | 60.3% |
| 95 | 50.0% |
| 90 | 39.7% |
| 80 | 22.3% |

注意：实际预算（V/uh）还受Reserve各元素真实库存与Affinity放大影响，不应把本表理论系数直接乘满额根系吸收上限16 V/uh。

## 7. 模型边界与后续验收

- 结果来自独立Python**确定性期望输入 + 每步1uh积分**，未运行仓库内Web游戏、CI域测试或千星节点图。没有进行随机元素球与随机出芽的蒙特卡洛模拟；尤其**第二叶与第二果的时间是平均等待代理，不是严格的随机变量期望值**。
- 当前方案被采纳的是**规则形状和数值校准基线**，不是对先前24/48/72/96uh体验目标的全部验收通过：每日首果晚2uh；隔天晚7uh；周玩家首果比168uh早30uh，且168uh第二片叶为LargeLeaf。不要改写成“小叶刚出生”。
- 每周玩家168uh Soil约2.58 V，Tree Reserve仍有61.36 V，实际预算0.420 V/uh：**接近低速**，但不是Reserve已经归零，也不存在休眠状态。
- 花期提前不构成单独问题，但采摘后复花Growth门槛、真实后续Bud机会、不同元素分布、较小uh积分精度、长周期产量、实际Web/Miliastra实现均未验收。
- 设计更新要同步 [growth-system.md](growth-system.md)、[growth-balance-baseline.md](growth-balance-baseline.md)、[growth-foundation-requirements.md](growth-foundation-requirements.md) 与 [uh统一规范](../../docs/plants/uh-time-unit.md)。不要用本轮期望轨迹冒充已落地的Runtime功能。
