# 水瓜厨房 MVP

本目录是“水瓜厨房”第一版 MVP 的开发入口，也是当前 MVP 的 source of truth。

目标平台是《原神·千星奇域》UGC。当前 MVP 不按照仓库根目录 `architecture/` 中的 Cordis + Godot 正式架构实现；这些架构文档属于独立的长期正式项目方向，不作为本轮千星奇域原型的开发约束。

新上下文进入开发时，先读本文件，再按“必读顺序”读取其余四份文档即可开始实现，不需要从历史对话恢复设计。

## 当前状态

**设计状态：核心闭环已收敛，可以进入实现。**

当前已经固定：

- 第一版 MVP 的目标、完成条件和明确不做内容；
- 千星奇域水瓜树的世界设定；
- 点击对象、史莱姆自动移动、劳动与搬运的基础交互；
- 七元素隐藏富集模型；
- 全局可调配置；
- 基于千星奇域服务器时间的离线衰减；
- 元素锁定的数据行为；
- 茎、叶、果实三个器官的元素亲和；
- 只显示最强元素颜色、不提供元素 UI；
- 七元素对果实六维口味的基础修正；
- 第一种元素反应：水 + 草 → 绽放 / 草种子性状体；
- 果实 → 水瓜汁；
- 1～3 份等体积水瓜汁混合及结果重算。

当前不需要继续扩展第二种元素反应、更多料理、顾客经营或多人系统，即可开始开发核心数据与玩法闭环。

## 当前核心闭环

```text
元素浇灌
↓
水瓜树隐藏七元素富集
↓
服务器时间衰减 / 元素锁定
↓
新器官生成元素快照
↓
茎叶：主元素显色
果实：主元素显色 + 口味 + 水草绽放
↓
采集果实
↓
制成水瓜汁
↓
选择 1～3 份水瓜汁混合
↓
重新计算元素 / 颜色 / 口味 / 绽放
↓
玩家观察结果
↓
反向决定下一轮培养
```

第一版要证明的是：**玩家会为了想得到某种水瓜汁结果，主动改变下一轮水瓜树的培养方式。**

## 开发切入顺序

当前设计已经足够支持以下实现顺序：

1. 建立全局 `ElementMvpConfig`，集中管理所有可调参数。
2. 建立水瓜树七元素状态、总容量、元素竞争和元素锁定。
3. 接入千星奇域服务器时间，完成初始化与读取时的离线衰减结算。
4. 建立茎、叶、果实的生成快照和器官亲和。
5. 接入主元素显色：主题色配置 + 素材颜色叠加 + 正片叠底，第一版 `ColorStrength = 1`。
6. 实现果实六维口味计算。
7. 实现水 + 草绽放与草种子性状体。
8. 实现果实取汁。
9. 实现 1～3 份等体积水瓜汁混合，并从最终元素组成重新计算结果。
10. 把上述步骤串成一次可玩的“培养 → 采集 → 制作 → 发现 → 再培养”闭环。

这里描述的是实现依赖顺序，不额外增加新的玩法设计。

## 尚未设计、不要自行补全

进入开发时，以下内容仍应保持未定义状态，不应由实现者自行扩写：

- 水瓜树具体的器官再生周期；
- 元素浇灌资源的具体获取方式；
- 元素锁定能力的获取、解除和表现方式；
- 第二种及之后的元素反应；
- 茎秆、叶片进入料理后的口味和用途；
- 草种子性状体作为独立材料的玩法；
- 更复杂的料理加工和配料；
- 顾客评价生成；
- 多人访问、材料交换和互动对树体的隐藏影响。

如果开发步骤触及这些边界，应先回到设计讨论，而不是自行补规则。
