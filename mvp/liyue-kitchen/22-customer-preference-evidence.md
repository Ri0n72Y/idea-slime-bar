## 4. 角色偏好提取规则

后续每位角色只从已有角色资料提取：

1. **明确表达**：角色直接说喜欢、讨厌、偏爱、无法接受某种味道或质地，可记录为正式偏好。
2. **实际行为**：反复主动选择某种食物、拒绝某种口感、对实际品尝给出明确反馈，可作为偏好证据；单次订单只说明本次需求，不自动等于长期口味。
3. **故事线索**：生活经历、职业、地域、回忆和饮食习惯可作为角色创作线索；没有明确感官指向时，不直接转换成偏好数值。
4. **缺少证据**：保持未定义，不补默认偏好、不按元素身份猜口味、不将角色背景刻板化成食物喜恶。

感官偏好只使用既有 sensory-mapping.md 的强度体系及05号词典的七元素、反应与质地语义。任何强度范围、权重或喜恶都必须能回指角色原文、实际行为或经用户确认的角色设定。

## 5. 后续角色资料的最小记录项

| 记录项 | 记录内容 |
|---|---|
| 角色身份 | 姓名、稳定ID、身份/职业/生活背景 |
| 故事依据 | 已确认的故事事件、对话或行为原文 |
| 感官偏好 | 对应入口/中段/回味、既有感官轴及明确喜恶/范围 |
| 反应与质地 | 已有反应标签、质地偏好及证据 |
| 元素属性 | 角色自身元素身份；缺少依据则未定义 |
| 揭示线索 | 玩家通过哪些故事、对话、订单或品尝反馈逐步获知 |
| 证据状态 | 明确表达、行为支持、尚未定义 |

不要求每个角色覆盖全部感官轴。偏好条目数量由角色内容决定；不为满足统一字段数量而添加无意义偏好。
