# 探索图谱、收集袋与无访客玩法验收

## 探索证据

一次成功领域命令产出稳定的 `GameEvent.fact + eventId + sourceId`；探索节点仅在首次匹配事实时完成，保存完成游戏日和证据身份。后续加工、交单、换种或清空截断事件日志，不会删除已经取得的完成记录。初始唯一种子拥有明确的 `SEED_OBTAINED` 开局事件。未完成的隐藏节点不出现在图谱、占位节点和完成数量中。

首期节点连接初始种子、播种、浇灌、有效夜间生长、首次成熟、手动收集经验、委托接受、完整果交单、剥壳、装杯及杯装果汁交单。隐藏节点「双元素滋养」要求真实灌注两种不同元素，触发前不给玩家展示内容。探索结果不因订单过期回退。新增版本只从旧存档中可核对的事件与状态回填发现，不为证据缺失的历史猜测成果。

## 省力科技

收集袋要求亲手收集三枚**不同 ID** 的真实元素球（已持久记录），再花费 **12 洞天仙力**永久开通。未满足资格或余额不足不改变世界状态；已购买不再扣费。

解锁前需要逐枚点击收集；解锁后可以一次性收取场景中所有现有球。每枚球仍沿用 `COLLECT_BALL` 的原始 50V、时间衰减、元素类型和唯一身份守卫。批量操作不增加 N，不增加 V，不改变 Growth/反应公式，也不会自动凝聚或浇灌。

按现有 N=8 的满额单日流程，不含播种、移物和临时查看：

| 日常动作 | 逐枚收集 | 收集袋 |
| --- | ---: | ---: |
| 凝聚全部 8 枚球 | 8 次点击 | 8 次点击 |
| 收集 8 枚球 | 8 次点击 | 1 次点击 |
| 将持有元素浇灌到指定地格 | 1–7 次点击 | 1–7 次点击 |
| 结束今日、确认、关闭简报 | 3 次点击 | 3 次点击 |
| **单日合计** | **20–26** | **13–19** |

对相同 8 枚球的操作减少 **7 次收集点击**；若每天凝聚不足 8 枚，则节省 `n-1` 次，其中 `n` 为实际待收集且可收集的球数。科技不会减少 8 次凝聚，后续可另行设计凝聚便利升级。多地格分配和可见工作台加工依然需要额外操作。

## 核心闭环与验证边界

`packages/liyue-kitchen/tests/batch-b.spec.ts` 在桌面鼠标与模拟触摸浏览器中分别从**新存档唯一 Seed** 出发，执行 Pixi 地格真实拖放、DOM 凝聚/委托、Pixi 球体真实点击、浇灌和夜间确认，取得首批资格。后续天数以同一生产版 `applyCommand` 重放完整 N/K 的逐次随机凝聚、收集、浇灌与逐小时 Growth，在真实成熟后恢复页面进行可视交互：完整果交单、探索证据、科技购买/批量收集、第二果剥壳/榨汁/装杯/交单、开垦外围地格与真实后续播种/生长。没有注入测试果实、种子或货币。

有效采摘保留一枚新 Seed，不依赖首单是否过期；失去委托仍可持续培育和接取新订单。禁止购买前批量收集、重复购买、伪造存档的检测由领域测试覆盖。

剩余可玩性问题：首次成熟所需夜晚仍依赖 N/K 和实际随机分布；每天全量凝聚仍存在重复点击；多格同时培育时 N 不倍增，需分配元素供给。主观视觉检查与真机触摸体验留到 U9 后统一处理。
