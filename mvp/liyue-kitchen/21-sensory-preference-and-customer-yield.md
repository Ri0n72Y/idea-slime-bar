# 角色偏好与顾客元素供给｜数值提案

> **状态：策划候选，等待用户校准。** 本文沿用既有感官强度体系，不另建G到感官强度的换算。G只用于元素物质账本与反应结算。

## 1. 已确认的设计依据

- [七元素感官评级与三阶段映射](../../docs/gameplay/sensory-mapping.md)已经定义强度数值：1/3/5分别是轻微、明显、强烈的参照锚点；强度连续、非负、不要求整数、不封顶。0表示已确认不存在；未定义表示缺少合法评级依据。
- 这些数值表示感官强度，不表示好喝程度、品质或喜好。三阶段使用同一组七元素感官轴。
- [05｜七元素感官身份与反应口感](../aquamelon-kitchen/05-sensory-identity.md)是感官语义词典；[06｜品尝数据合同](../aquamelon-kitchen/06-flavor-contract.md)规定物质输入与计算边界。
- `E_free[7]`、`Products[]`及`M`属于物质账本，单位G。物质占比不能直接当作感官强度；已消耗自由元素不能重复计味。
- 现有阶段表和反应表描述时间倾向、阶段强调与标签，**不构成固定数字系数**。当前尚无完整的物质组成到三阶段连续感官强度的计算公式；无合法映射时保留「未定义」，不以G替代强度值。
- 每位顾客有身份、背景和故事链；绝大部分顾客有口味偏好。顾客自身元素属性决定留下哪一种元素，口味偏好和互动决定留下的量，两者分开。

## 2. 材料数据与品尝结果分层

### 材料事实

- 完整果实及加工材料保留各自真实的物质事实：自由元素、当前反应产物、产物方向与感官身份。
- 一果2000ml、四杯各500ml；果汁、果肉、果壳按原果平均元素性状继承，同批四杯采用相同平均性状。该继承规则不等于物质账本复制，也不要求材料间元素性状守恒。
- 平均性状的具体字段和上游计算仍待明确。不得把Affinity直接当成感官强度，也不得把G物质量占比当成感官强度。

### 品尝结果

每次「尝一尝」按既有合同输出：

- Entry：入口阶段七个感官轴的强度值或「未定义」；
- Body：中段阶段七个感官轴的强度值或「未定义」；
- Finish：回味阶段七个感官轴的强度值或「未定义」；
- 各阶段标签及整体标签。

感官描述在品尝时派生，不另存为一份可消耗物质账本。首个反应产物锁定外观身份；品尝时仍按当前真实存在的全部Products及其感官语义判断。

**本提案不重新定义强度数值，不从G计算强度，也不把阶段描述转成固定倍率。** 后续只有在正式感官映射规则得到明确设计与确认后，才可以计算具体品尝数值。

## 3. 沿用既有强度数值

| 数值 | 既有含义 |
|---:|---|
| 1 | 轻微：确实可察觉，但局部、柔和或短暂 |
| 3 | 明显：稳定且容易辨识，成为阶段主要特征之一 |
| 5 | 强烈：显著主导阶段体验，甚至改变其他基调的呈现 |
| 0 | 不存在：已明确确认该基调没有可感知表现 |
| 大于5 | 超强及极端：继续累积，完整保留实际数值 |
| 未定义 | 未知：缺少合法评级依据，不能当成0 |

1/3/5只是理解强弱的参照位置。实际值可以是任意连续非负数，不取整、不截断到5、不压缩或归一化。

七元素的阶段倾向、各反应的阶段表现与标签，直接沿用 `sensory-mapping.md` 第3、4节及05号感官词典。原表是定性阶段映射，不增加新的比例系数。

## 4. 顾客偏好数据模型

每位顾客至少具有：

- `characterId`、身份、背景、`storyChainId`；
- `elementIdentity`：决定留下的元素种类；
- `preferenceProfile`：感官轴、反应和质地偏好；
- `revealedClues`：玩家已经通过故事、对话、订单或品尝反馈发现的线索；
- `visitState`：本次到访的互动、品尝和结算事件，防止重复领取。

### 偏好表达

采用稀疏偏好，不要求每位角色填写全部感官轴：

- **感官轴偏好**：指定入口/中段/回味及感官轴，配置可接受强度范围 `[L,U]`、范围外容忍距离 `τ`、重要度 `weight`。数值直接使用既有感官强度体系。
- **反应偏好**：喜欢或排斥已有反应标签，可进一步指定强度范围。
- **质地偏好**：例如冰块、晶冻、果粒、爆珠、微振等已有质地标签。
- 每位角色先配置2–4条显著偏好作为内容制作建议；偏好数量和揭示顺序由角色故事决定。

### 偏好匹配（新候选）

对已定义的实际强度 `x`、目标范围 `[L,U]`和正数容忍距离 `τ`：

\[
d=\max(L-x,0,x-U)
\]

\[
match=\operatorname{clamp}(1-d/\tau,0,1)
\]

同一顾客按重要度加权：

\[
TasteMatch=\frac{\sum_j weight_j\times match_j}{\sum_j weight_j}
\]

- 未配置的偏好不进入分母。
- 实际强度为「未定义」时，不当成0，也不参加该轴的匹配计算。
- 反应和质地标签按喜欢/排斥规则匹配；不能把缺少的标签伪装成某个强度值。
- 隐藏偏好用于确定真实反馈，玩家只通过故事和实际体验逐步发现线索，不直接显示内部数值。

### 真实角色偏好资料

真实角色的偏好不使用虚构角色A/B代替。当前已有角色证据与缺失项见[22｜现有顾客角色与偏好证据清单](22-customer-preference-evidence.md)。在角色资料明确给出感官偏好前，不填写示例数值或推断实际偏好。

## 5. 满意度与顾客元素供给

沿用20号经营候选中已分开的两项来源：

- `I`：本次到访是否完成一次有效问候/有意义互动；完成为1，否则为0。同一到访只结算一次。
- `S`：顾客实际品尝后的满意度，首轮候选取`TasteMatch`，范围0–1。没有实际品尝时不产生品尝满意度。

候选供给公式：

\[
V_{leave}=5I+25S
\]

其中互动5V、服务系数`k=25`沿用20号量级试算候选，尚未批准为正式配置。

| 有效互动I | 满意度S | 留下元素 |
|---:|---:|---:|
| 0 | 0 | 0V |
| 1 | 0 | 5V |
| 0 | 0.8 | 20V |
| 1 | 0.8 | 25V |
| 1 | 1 | 30V |

元素种类由顾客`elementIdentity`决定，全部进入对应Eco通道。互动与品尝分别记录唯一事件ID；同一顾客同一次到访不得通过重复对话或重复提交无限产出。

故事进度与满意度分账。既有餐厅合同没有上菜等待时间惩罚，本轮不新增等待扣分；高满意度也不能自动跳过角色故事条件。

## 6. 当前缺口与实施边界

- **感官数值映射未完成**：当前资料定义了强度标尺、七元素语义和反应阶段倾向，但尚未给出从真实材料事实到三阶段强度数值的完整规则。不能以G代替，也不能凭空增加阶段系数。
- **加工平均性状算法未完成**：11号已确认果汁、果肉、果壳及四杯的平均性状继承方向，具体字段和算法仍需确定。
- **代码尚未实现**：main当前`processing.ts`的`JuiceBatch.traits`复制`lockedAffinity/baseAffinity`，它是亲和度，不是品尝强度；`visitors.ts`目前只有阿砚的固定访客故事状态，没有通用顾客偏好、元素属性和满意度模型。
- 当前具名角色资料仅能确认阿砚的商路故事与杯装水瓜汁委托；感官偏好、元素属性及实际品尝反馈均未定义。D1首位客人也尚无角色档案，详见[22号清单](22-customer-preference-evidence.md)。
- 本文只提出偏好匹配与供给候选，不授权Coder实施，也不修改现有成长、反应或材料账本。

## 7. 后续校准案例

1. 强度1、3、5及大于5的值应按原数值体系参与偏好匹配，不换算成G。
2. 已确认不存在的0与缺少依据的「未定义」必须得到不同结果。
3. 同一组阶段强度面对两名不同偏好顾客，应产生不同匹配结果。
4. 同一顾客面对两组合法阶段强度，应产生不同匹配结果。
5. 某阶段强度未定义时，该轴不参加偏好匹配，不以0补齐。
6. 反应标签与质地偏好按既有反应感官身份判断，不重复计入已消耗的自由元素。
7. 同一到访重复对话、重复提交不能重复领取互动和服务V。

本轮只沿用既有感官强度体系并调整顾客偏好提案；没有新增G到强度的映射，没有修改源码，也没有把候选写入正式平衡配置。
