# 璃月厨房 — UI-driven 开发清单 v0.4

> 本轮正式采用 UI-driven、可视/可玩/可交互的纵向切片开发。游戏仍使用千星奇域单机 Lua；已有水瓜数值合同不变。这里定义开发顺序、可交付的屏幕对象与验收证据，是 **MVP 实施工作的主 checklist**。
>
> 状态：开发流程/检查清单已确定；细节中的 K/N、价格、首果时间及物质分账仍须相应设计关口定稿。任务打勾只能依据当前游戏内实机证据，不因文档写好或 Lua 函数存在而标为完成。

## 1. 工作规则

1. **从玩家能看见/点击的物体开始**。按 `可见物体 → 输入动作 → Lua Game 真实状态变化 → 屏幕反馈 → 错误/边界反馈` 提交一个完整小切片；不要先独立完成庞大后台框架再集中做 UI。
2. **一张主屏先跑通**。16:9 固定柜台：左上访客、中央洞天水晶球、右侧委托和探索、球下仓储、左右加工；新增界面只按需浮层展开。不开发尚无可见使用入口的隐性系统。
3. **每个可交互控件有合法状态和 Guard**。点击后请求同一权威 `Game` 操作；只有成功才扣物、领奖、播放成功反馈；禁用状态可说明原因。UI 不留第二份事实账本。
4. **优先实物交互**。项目已验证 Lua 按名称更新文字/响应基本点击，尚未验证可靠拖放/动态图片/存档；MVP 先以「选中物品→点击目标」实现合法的放置/转移/设备投料，实机验证后再加拖拽。静态编辑器资源可以用占位美术，但按钮行为不可用假数值代替。
5. **逐切片可玩、可复测、可展示**。每完成一个切片，都要能打开对应千星场景，从用户操作达到可见结果，并留下短录屏或连续截图、编辑器资源绑定清单、关键事件/状态证据及未验证项。不得只依据 Lua 单测、Web 预览或生成脚本称为千星实机通过。
6. **旧数值不重写**。无论屏幕按钮先实现哪个部分，接入植物时必须调用已批准的 Soil/Reserve/Growth/Affinity/反应逻辑；新昼夜层只在手动结束当天时推进 `K uh`，不能用脚本直接给玩家生成成熟果来伪装实际流程。
7. **按玩家操作路径排序，不按技术模块排序**：优先保证开局能操作物体、连续玩若干天，随后补齐加工/订单/探索/仙力扩建；任何阶段结束都保留一个可运行的真实垂直切片。

## 2. UI 对象与行为合同

| 屏幕元素（稳定显示/按钮名示意） | 看得到的内容 | 玩家动作 | 真实状态/合法性 | 最小可见反馈 |
| --- | --- | --- | --- | --- |
| `LK_C_Day`, `LK_B_EndDay` | 第几天、结束今日 | 点击结束当天 | 一次推进 K uh + 唯一日结；不能重入 | 次日、阶段变化/日结报告；未收集球提示 |
| `LK_C_Visitor`, `LK_B_Talk` | 访客立绘/对白/来物 | 交谈、领取剧情种子 | `visitorEventId` 一次性发物/发奖励 | 物品出现在实际库存、仙力变动、获得线索 |
| `LK_C_CrystalBall` | 透明水晶球、7 个六边形格 | 选择格子/查看树/放物 | `plotId=1..7`，球地面对象独立于土壤 | 格子高亮，打开合法操作与地面物品 |
| `LK_C_Plot01..07` | 中心1+外围6，已开放/休眠状态 | 开垦、种植、查看 | 未解锁无法种植；每格最多一树，独立 Soil/Plant | 支付后解锁、种子真正进入该格、状态更新 |
| `LK_B_Condense`, `LK_C_Balls` | 今日 N 次、随机元素球 | 凝聚/收集/指定地块浇灌 | 共用 N；每球纯元素固定 50V；仅对已开放地块增 Soil | 球减少、次数递减、土壤/树可观察变化 |
| `LK_C_Ground`, `LK_C_Storage` | 球内地面物品、球下仓储物品 | 放下/拾起/转移/选中 | 真实 `itemId` 的容器与位置转移，不复制 | 物品从源位置消失并在目标位置出现 |
| `LK_C_ShellStation`, `LK_B_Peel` | 剥壳台、原果/果肉/果壳 | 对真实原果剥壳 | 消耗完整果 `itemId`，产果肉+果壳；元素账本只随一个载体转移 | 原果消失、新材料出现、非法原料拒绝 |
| `LK_C_Juicer`, `LK_B_Juice` | 榨汁机、投料 | 对去壳果肉榨汁 | 果肉消耗→唯一原汁，完整账本单向继承 | 原汁可选中，不能复制/重复榨 |
| `LK_C_CupStation`, `LK_B_FillCup` | 空杯/原汁/成品 | 装杯 | 空杯+原汁各消耗一次→杯装果汁 | 成品杯出现；缺空杯则明确失败 |
| `LK_C_OrderPanel`, `LK_B_Deliver` | 完整水瓜或杯装果汁委托、截止日 | 接单/交单 | 真正消耗相应成品；截止第 D 天白天有效、进入 D+1 过期 | 完成/过期状态、奖励及物品变化 |
| `LK_C_Discovery` | 新发现提示、节点与连线 | 打开地图、点节点 | 通过真实事件完成/解锁，隐藏节点不泄漏 | 已完成高亮、条件/线索、历史证据 |
| `LK_C_AdeptalEnergy`, `LK_B_Unlock` | 仙力余额、开垦/技术费用 | 买地格/解锁工具 | 奖励按源事件去重、支付原子扣费，余额不能负 | 地格解锁、余额更新、操作能力真实变化 |

控件名是建议的 **UI 绑定键**，须在千星编辑器确认资源层级/名称后才视为实际契约；`itemId`、`plantId`、`plotId` 永远不等于固定 UI 槽位 ID。对于图形控件，静态布局/资源 ID 必须创作者导入与绑定。

## 3. 逐屏可玩切片（实施及验收 checklist）

### UI-00：可点击的主场景骨架

- [ ] 16:9 单屏里能看见访客位、水晶球七格、右侧委托/探索入口、球下仓储、左右剥壳/榨汁装杯区、日期和结束今日按钮。
- [ ] 七格固定蜂巢布局「中心1+外围6」，能区分已开放与休眠格；初始可用格数由配置决定，候选1格。
- [ ] 点击至少一个实际千星 UI 控件可显示选中/取消选中/不可用状态；所有静态占位控件标明不可用或隐藏，不假装功能已实现。
- [ ] **验收**：真实千星运行画面截图 + PC 鼠标操作短录屏 + 编辑器元素名称/资源绑定清单。此阶段只称「UI 可点击」，**不声称可玩闭环完成**。

### UI-01：访客交付种子 → 水晶球种植

- [ ] 玩家点击开场仙人对白，真实收到独立 ID 的种子，访客重复交谈不会再送。
- [ ] 种子在仓储/玩家持有处可选中；点击开放地格完成播种，种子实物消耗，格子出现真实 Seed。
- [ ] 点击未解锁格显示开垦条件，不可直接播种；同格第二次播种提示占用。
- [ ] 初始「一粒水瓜种子」探索记录可响应真实获得事件（完整图谱在 UI-07 扩展）。
- [ ] **验收**：开局→收种→选地→种下→再次点击拒绝；UI 和 Game 中种子、树数保持一致。

### UI-02：每日凝聚/收集/浇灌 → 结束今日 → 次晨生长

- [ ] 显示当前 N 和使用次数；每次凝聚生成一个真正随机单元素、初始 50V 的球，N 用完禁用。
- [ ] 玩家选择元素球并浇灌到开放地格的 Soil，球实体减少/消失；不误入其他地块。
- [ ] 结束今日后推进统一 K uh，按已有领域规则结算根系、生长及成熟条件；次晨显示日期、至少一项真实 Growth/阶段变化、凝聚额度重置。
- [ ] 计算覆盖跨模型日 04:00 等合法事件；日结不可重复提交，不因 UI 刷新重复结算。
- [ ] **验收**：连续多日的真实播种→浇灌→生长截图/视频；对应 Debug 账本和阶段轨迹可复核。K/N 未锁定前用明确标识的校准配置。

### UI-03：采摘、地面暂存与仓储

- [ ] 真实成熟水瓜出现在树上，点击采摘从活体果变成有独立 ID 的完整水瓜。
- [ ] 选择物品，放在水晶球地面，再拾起/转移到球下仓储和工作区；仓储项可移回地面。
- [ ] 锁定格不接受种植；地面临时物品不会在换日、切窗后消失或占用树位。
- [ ] **验收**：一次合法采摘与三处空间移动；物品总数和 G 账本未复制，未成熟果不可领取成功反馈。

### UI-04：三步真实加工

- [ ] 工作区可显示/选中完整水瓜、去壳果肉、果壳、原汁、空杯、杯装果汁。
- [ ] 完整水瓜→剥壳→果肉+果壳；果肉→榨汁→原汁；原汁+空杯→装杯→杯装果汁。
- [ ] 每步输入消耗和输出产生对应真实物品 ID；`E_free[7]/Products[]` 不在多个容器重复存在；缺原料/容器明确拒绝。
- [ ] **验收**：从实际采摘的果实手动加工出一份杯装果汁；第二次操作已消耗原料失败，完整账本可追溯。最小分账合同须先由 Lead 批准。

### UI-05：右侧限时委托的完整交付

- [ ] 右侧显示真实访客订单，只有完整水瓜/杯装果汁两类、数量、剩余游戏日与奖励。
- [ ] 仅对应真实成品可交付，交付成功后消耗实物、变更订单状态并发放一次奖励。
- [ ] 截止第 D 天白天仍可交；结束第 D 天进入 D+1 后未完成变过期，过期不能领奖；后续订单仍可继续。
- [ ] **验收**：水瓜单与果汁单各成功一次；再验证错物品拒绝、到期当天可交、过期不可交、重复提交不重复领仙力。

### UI-06：洞天仙力与解锁第二地格

- [ ] 访客真实事件、有效种植周期、成熟果采摘、订单交付可增加仙力，余额显示更新；重放同一事件不再奖励。
- [ ] 点击锁定的蜂巢地格打开价格/购买，余额不足拒绝；支付一次后永久解锁该格。
- [ ] 新地格可真实播种、浇灌和夜间生长，与第一格 Soil/Reserve/Tree 互不串账，N 仍为全洞天共享。
- [ ] **验收**：可通过正常劳动从初始一格积累仙力买到第二格，实际同时种两棵树；重复购买不扣第二次费用。

### UI-07：探索地图与第一项便捷技术

- [ ] 右侧探索入口可展开图谱，已完成/可见/部分线索/隐藏节点显示符合设计，不泄漏隐藏条件。
- [ ] 从访客赠种、播种、首次成熟、剥壳、装杯、交单和合法元素反应事件自动完成对应节点，历史证据不随物品消耗消失。
- [ ] 玩家经过指定的真实重复收集经历后，可用仙力解锁一项批量收集工具；工具实际减少原有重复点击，并严格扣除真实元素球。
- [ ] **验收**：在同一存档通过实际动作点亮至少数个节点，独立触发一个隐藏反应节点，完成一次技术消费和可复测的效率提升。

### UI-08：整体验收与体验调校

- [ ] 无 Debug 指令，手动完成「访客赠种→种植→浇水→多晚生长→采摘→水瓜交单→加工→果汁交单→解锁地格→探索发现→解锁技术」。
- [ ] 通过多种随机元素供给轨迹测量首果游戏日、首单成功率、仙力收入、第二格解锁日和每日操作数量；据此校准 K/N、订单期限和升级价。
- [ ] 验收异常输入：双击/连续点击、换日时的材料转移、同一物品跨容器移动、订单过期、奖励重入、格子锁定、余额不足、图谱关闭重开。
- [ ] 如果千星实机支持持久化，验证读档后天数、物品、格子、订单、仙力与发现不重复、不丢失；未验证不得宣称存档功能完毕。
- [ ] 只做必要的可读性/操作反馈和视觉打磨；没有正式素材的区域可先用一致占位图标，确认功能后再逐个换美术。

## 4. 单个 checklist 条目的完成定义

**Done 的必要条件（缺一不可）**：

1. 编辑器里存在实际可见/可用的对象或窗口。
2. 玩家能通过实际鼠标操作触发，不要求手动在 Debug 输入函数。
3. 相应 Lua 领域状态发生一次合法且可追溯的变化。
4. 画面有明确成功或失败反馈；非法操作无副作用。
5. 截图/录屏 + 本次变更来源文件 + 必要编辑器绑定记录可以由另一人复现。
6. 若依赖未经批准的配方、数值或未验证编辑器 API，标记 Blocked/Unverified，不为了打勾制造假交互。

**实施任务粒度**：一个任务卡对应一条可操作流程（一个屏幕物体或相邻的输入→反馈组合），任务描述包含 `UI对象 / 玩家动作 / Domain调用 / 成功状态 / 失败状态 / 实机证据 / 依赖`。不要按“完成全部 Game.lua”“编写所有数据模型”拆任务。内部纯逻辑函数跟随当前可玩切片实现。

## 5. 技术边界与下一步

- 千星编辑器负责布局、图片资源、控件绑定；本地 Lua 负责唯一 Game 状态、按钮交互、状态机、昼夜计算、委托、探索、仙力。暂不引入 Web、服务端或多人。
- 真实拖拽、缩放图谱、动态切图与存档需要实机验证。若无法实现，采用稳定、可玩的替代控件，而非删除相关玩法。
- **第一批实际开发任务：UI-00 → UI-01**。先交付可以点击的柜台和七格水晶球，再让仙人真正交付种子、玩家真正播种；完成后才进入 UI-02 的元素与夜间生长。
- 原有 `mvp/aquamelon-kitchen` 继续充当生长/元素规则来源；`mvp/liyue-kitchen` 中的文档决定新的画面、昼夜、经济和互动流程。若有规则冲突，停止对应切片，交 Lead 定义，不得自行改写旧公式。
