# 访客与剧情交互验收

## 可玩事件与真实身份

首段访客「阿砚」的身份固定为 `visitor:yan`，仅在玩家完成首次有效夜间生长（A03）且进入第 2 天后到访。访客出现不阻断无访客种植、加工和委托主线。

| 实际对话行为 | 持久结果 | 仙力与守卫 |
| --- | --- | --- |
| 首次问候 | 记录结识日和 `VISITOR_MET` | 首次 +2，来源 `visitor:yan:greet` |
| 询问商路线索 | 探索隐藏节点 V01，保留事件和来源 | 首次 +3，来源 `visitor:yan:clue` |
| 收下旅人木牌 | 发放 `item:visitor:yan:woodtag`，放入原物品栏 | 一次性赠物，无仙力 |
| 询问送货任务 | 使用 U5 `createOrder` 创建 `juice_cup` 访客委托 | 同一 `orders` 账本，按截止游戏日计算 |
| 按时实际交付杯装果汁 | 消耗唯一真实 `AquamelonJuiceCup.itemId`，入账订单仙力 | 沿用 U5 按订单去重 |
| 听取真实交单谢意 | 隐藏节点 V02，记录 `VISITOR_THANKED` | 首次 +4，来源 `visitor:yan:thanks` |
| 重复闲聊 | 只更新对话文本 | 不生成物品、订单、发现或仙力 |

上一步尚未完成时，后续选项不出现或由领域拒绝；同一个奖励来源无法再次入账。赠物 `VisitorGift` 可移动到物品栏、仓储和水晶球地面，不能播种、剥壳、榨汁、装杯或充当委托材料。其 `visitorId + eventId` 和已领取标记共同验证，刷新后不会再次发放。访客没有第二次开局 Seed 的创建权限。

同一时期委托板和访客委托可以同时显示及交付。委托板的常规轮换只检查 `visitorId=board` 的订单，访客订单不会阻断其到期续单。访客单过期后，可经同一对话重新发布一个新 ID 的任务；之前已过期订单作为历史保留，不能重新领奖。剧情谢意必须以完成过真实访客订单为前提。

## 存档和验收

世界状态版本提升到 v6。v1–v5 迁移新增空的访客进度，保留旧物品、Growth、订单、仙力、探索等账本。存档拒绝重复/伪造赠物 ID、伪造访客订单和会话状态/奖励不一致；所有事件以现实玩家触发的 `TALK_VISITOR` 与 `DELIVER_ORDER` 正式领域命令产生。

领域测试核对交谈/线索/赠物/订单/谢意的守卫、双订单共存、过期后重新发单、材料和仙力守恒、读档。Playwright 桌面鼠标 1600×900 和模拟触摸 1280×720 分别从全新唯一种子出发：真实拖拽播种→凝聚球/收集/浇灌/夜间确认→访客真实对话选项→领取并移动木牌→领取访客委托。随后用生产版 `applyCommand` 重放多日随机凝聚、浇灌和逐小时 Growth，以缩短自动化时间；成熟之后恢复 UI 真实指针点击采摘、拖入加工台、剥壳、榨汁、装杯并交付，再领取谢意和检查 V01/V02，刷新后核对四项账本。**多日加速不等于玩家逐日手动完成全部点击**；不注入果实、种子、仙力或测试专用物品。
