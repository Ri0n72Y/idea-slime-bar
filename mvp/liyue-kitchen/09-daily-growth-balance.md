# MVP｜以 1d 为单位的日终种植与 Growth 数值提案

> 状态：2026-11-19 数值策划草案。玩家已确认经营优先、关店后集中浇灌、每日随机6–10球及 1d 时间口径。以下数值换算、曲线和委托候选待 Lead/用户审定；当前代码仍按旧 24uh、N=8 执行。此文档不授权直接修改代码。

## 1. 游戏日合同

- 玩家主要在工坊经营：接待顾客、接单/交付、加工、整理和收集。水晶球用于进入种植区；营业时可查看及采摘成熟果。
- 玩家点击「关店」后进入种植区的当日浇灌阶段。当天允许**一次集中浇灌提交**：从已收集或储存的元素球中任意选择数量、元素类型及接收地格；确认前可编辑多个地格的分配，确认后当日不得再次浇灌。可以选择零投入。
- 玩家确认「结束今日」推进 **1d** 的世界成长和经营结算，展示次晨报告并进入下一营业日。营业与整理/布置期间世界时间不自动增长。
- 初始只开放一格，多地格开放后仍共享同一批元素球；每天一次浇灌提交可以同时给多格分配养分。各格继续保持独立的 Soil/Reserve/Growth 状态。
- 与原文档对应的阶段：DAY_START → WORKSHOP_OPEN → CLOSE_SHOP → GARDEN_WATER → DAY_RESOLVE(1d) → DAY_START(d+1)。关店后不再接受当天顾客交易，截止日仍包含该日营业时段。

## 2. 每日随机供给

| 参数 | 原试玩实现 | 新游戏日合同 |
| --- | --- | --- |
| 球数量 | 玩家主动凝聚固定上限 N=8/日 | 每个游戏日自动生成 N_d ∈ {6,7,8,9,10}，五个数量等概率（初版假设，Buff可调整） |
| 元素类型 | 七种等概率，独立随机 | 每球七元素独立等概率抽取，允许同元素多球，不保证七元素齐全 |
| 球初始量 | 50V/球 | 保留50V/球 |
| 每日总供给 | 固定400V/日 | 300–500V/日，期望400V/日 |
| 生成时机 | 玩家点击凝聚 | 当日营业期间自动出现的收集对象；MVP候选为开业时一次确定本日球集合 |
| 浇灌入口 | 按元素逐次 WATER_PLOT | 关店后将选择的全部元素球/已收集V一次提交至各目标地格 |
| 随机重放 | 存档种子驱动 | 同一存档种子及动作序列完全重放；生成数量和每枚元素类型均消耗持久化 RNG |

每日平均约有4.96种不同元素出现（N=8、七元素独立随机时的数学期望）；同一天可能缺少任何指定元素。未引入特殊Buff时，不增加保底、水/草强制生成或指定元素修正。

已收集的元素养分维持现有 heldElements 的真实V存量，可跨日选择使用，不额外生成或复制。**跨日持有的库存容量/损耗是否调整待Lead确认**；当前代码没有此项上限。未收集的临时元素球在日终成长后按原衰减规则消失，营业阶段暂停时不因实际时间而损失V。具体物件保管与水晶球区域职责见 [10-workshop-first-layout.md](10-workshop-first-layout.md)。

## 3. 时间单位迁移：24uh = 1d

面向玩法、领域配置、成长速率和验收报告统一用游戏日 d。原uh数据只用作**迁移参照**；不再作为玩家可见的倒计时，也不继续按一周现实上线频率设置产量目标。

| 量 | 原数值 | 换算到 1d 的初版校准基线 |
| --- | ---: | ---: |
| 夜间世界推进 | 24uh | 1d |
| Soil 保留 | 0.99/uh | 0.99^24 = **0.785678/d**；任意Δd保留 0.785678^Δd |
| Seed 根系速率上限 | 2 V/uh | **48 V/d** |
| Seedling 根系速率上限 | 1.85 V/uh | **44.4 V/d** |
| Sapling 根系速率上限 | 16 V/uh | **384 V/d** |
| Sapling Reserve 参考 Growth 速率 B0 | 5.4 V/uh | **129.6 V/d** |
| Soil 总容量 | 1000V | 1000V，不随时间单位变化 |
| Reserve 容量 | 180V | 180V，不随时间单位变化 |
| 球半衰期 | 0.25uh | 1/96d；不改变营业期暂停的实际行为 |
| 合法随机出芽机会 | 模型04:00，每24uh最多一次 | 每d最多一次，在当日固定内部相位结算；与100G周期出芽去重 |

**日速率不等于整日实际结算量**。实际根系吸收受 Soil、七通道、Reserve 充盈函数限制；预算还受亲和、亲代/子代分配与储量截断。不得简单用「日上限 × 当前状态」算出整夜Growth，也不得把一次1d直接套进非线性函数而忽视中途跨越阶段阈值。

首次实现建议保持真实积分，内部子步表示为 Δd=1/24（或更细的事件驱动步），每次按 Δd 对速率和保留率计算；用户和数值规格仅使用 d。若后续想改成单一日步，须用以下轨迹验证结果等价，再定替代近似公式。

**领域机制继续保留：**
- 七维固定顺序与物质账户 V → G、RootPreference/TreeAffinity分工、Soil共享吸收、Sapling Reserve充盈限流及S型预算 (M=95V,W=12V)、每元素独立预算和缺元素不互补。
- 树45/90G；Bud20G；叶26G；生殖12/40/90G（同一连续生殖账户）；每叶30%名义Tree预算，母叶生殖80%/成熟40%，LargeLeaf本体60%效率。
- 实体亲和继承率0.5、ExtraAffinity=1、最多三叶、Tree100G周期出芽及每日随机出芽。每日投签在固定内部相位进行，不能因结算子步数量变化而增加次数。
- 成熟果90G后富集、150G自然停止与七元素反应遵循原独立合同；**1U=30G是反应份额，和1d无关**。

规则依据：[七维数值](../aquamelon-kitchen/02-data-and-balance.md)、[器官成长](../aquamelon-kitchen/03-growth-and-harvest.md)、[当前实现](../../packages/liyue-kitchen/src/domain/growth.ts)。

## 4. 1d 曲线：D1播种，D7早晨首果

**复算方法**：将当前 growth.ts 的逐时积分算法按 1/24d 相位转为离线对照模型；先以固定8球验证 Soil/Reserve/成长阶段与仓库 [U2-BALANCE-TRACE](../../packages/liyue-kitchen/U2-BALANCE-TRACE.md) 在D2–D7吻合，再进行新的随机供给回放。采样为512个确定性seed：0x17a5b7e1 + 1009×i（i=0…511），每个营业日先随机取6–10球，再对每个球七元素等概率抽取；所有当天球一次集中浇到P01，夜晚积分1d；不提前采摘或加工。**这些是数值策划离线复算，尚非新版本生产代码测试**。首果以前没有实际反应，故不涉及成熟后的反应近似。

| 次晨 | 阶段目标 | 512样本中观测状态 | Soil期望(V) | Reserve期望(V) |
| --- | --- | --- | ---: | ---: |
| D2 | 看见种子成长反馈 | 全部Seed | 290.2 | 0 |
| D3 | 出苗 | 全部Seedling | 512.7 | 0 |
| D4 | 第一株幼树、开始进入Reserve | 494/512 Sapling，平均0.68叶 | 616.8 | 127.7 |
| D5 | 叶片生长并开始开花 | 全部Sapling，平均1.45叶 | 626.3 | 152.0 |
| D6 | 青果积累阶段 | 全部Sapling，平均2.15叶；尚无熟果 | 640.3 | 150.1 |
| D7 | **首次可采摘成熟果** | 511/512有熟果，平均1.37熟果 | 638.6 | 147.7 |
| D8 | 首果最晚容错日 | 512/512有熟果，平均2.01熟果 | 626.5 | 144.7 |

以上是完整收集与每日集中浇灌的拟定基准，不能当成所有玩法必定在D7有果；每个状态仍以真实阈值判断，不能第7天直接发放果实。

## 5. 合法策略差异：同一512种子

| 操作策略 | 第7天首果 | 第8天首果 | 第9天首果 | 首果p50 / p90 |
| --- | ---: | ---: | ---: | --- |
| 每日全收集并浇灌 | 511 | 1 | 0 | D7 / D7 |
| 每日只选前⌊N_d/2⌋枚球浇灌，其余放弃 | 0 | 342 | 170 | D8 / D9 |
| 每逢第3个营业日不浇灌，其他日全浇 | 390 | 122 | 0 | D7 / D8 |
| 只浇当日水/草元素球（其余放弃） | 0 | 0 | 11 | D11 / D12（最晚D15） |
| 奇数日收集入袋、偶数日统一浇灌两日球 | 12 | 500 | 0 | D8 / D8 |

这一对照用于展示策略代价，不主张强制玩家每天收尽所有球。偏好水/草虽然亲和较高，但单独选择两种元素会受到其它通道缺失与预算不互补影响，首果明显延后。完整投入平均在首果前产生约166V累计土壤溢出；奇偶日集中储存策略约442V，显示储存/浇灌时机也有真实代价。数值为离线对照，不纳入已经完成的正式验收证据。

**本轮判断**：暂不调整 Growth 核心倍数、阶段阈值和土壤容量。随机生成6–10球后，积极玩家仍大多D7首果；收集比例、断水、元素偏好带来差异。先验证新1d实现对账，再决定是否需要压缩/放宽分布；避免同时改输入、S曲线和阈值使归因失效。

## 6. 经营联动与待确认数值

- 由于顾客与制作是每日主循环，D7左右的果实可以在营业期采摘、加工、交单；种植是每天关店后的集中决策。首张完整水瓜单建议先测试 **D1发布，D15截止（+14日）**，相较旧D46有经营压力且给D8/D9首果留出空间；后续订单 **+12日** 仅为候选，要在种子续种、多格平分资源与两类订单交替下复测。
- 洞天仙力奖励6/2/16、地格费用8/16/24/32/40/48先不动，避免与新的随机产能和经营节奏同时调整。初期第二格开启后仍只共享全洞天6–10枚/日，必须针对“两格各分一半”“一格优先”“轮灌”补证据。
- 不以降低手势次数为独立目标。主要观察首次订单成功率、每天是否有有意义的制作/收集决策、养分分流带来的器官/风味差异，以及开垦后资源竞争。

## 7. 实施与验收边界

1. Lead/用户确认新1d合同、每日球生成时机、一次浇灌提交/跨日储存语义、首单期限后，再委派Coder迁移领域和UI。
2. Coder改动时复用既有确定性领域测试/模拟，不新建大规模框架。先复现固定8球旧轨迹的等价性，再对照随机6–10球512样本分布（批量可减为固定种子小样本作为CI验收）；实际流水须分别记录自然蒸发、根吸收、Reserve支出、各器官G和浇灌溢出。
3. 独立Reviewer核对1d的分数步积分、事件去重、日终物质守恒和随机重放；Lead决定参数及合并，Experience QA待统一体验验收节点执行。
4. 本提案进入正式设计版本后，需同步更新旧 [01-day-loop-and-ui.md](01-day-loop-and-ui.md)、[README.md](README.md) 与 [uh-time-unit.md](../../docs/plants/uh-time-unit.md) 中的旧时间和上线频率表述，避免并存矛盾。
