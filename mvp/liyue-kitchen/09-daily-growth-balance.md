## 1. 每日玩法与教程终点

- 游戏以**制作经营、资源收集**为主：白天在工坊接待顾客、购买或订购 NPC 原料、制作饮品/餐点/药剂、交付订单，同时收集元素球；通过水晶球进入独立种植区。
- **D1当前开局**：水晶球已在店铺左侧、第一块土地的七维Soil合计**1000V**且已充盈，种子在地上，储藏区有一个普通外观的初始水瓜，右侧任务板指引播种和加工交单。当前不出现NPC补土剧情、赠送道具或NPC现场教学；剧情版NPC送来充盈水晶球、赠果和品尝的情节另行归档，不作为本阶段实现要求。
- **种植、浇水与维护安排在每天早晨**：玩家进入水晶球管理园地、使用已收集的元素球浇灌；D1土地已充盈，任务只要求播种，不强制额外浇水。日间可经营、加工与收获。玩家确认「结束今日」后推进**1d（24uh）**真实成长，次晨反馈夜间变化；不再采用关店后才允许浇水的规则。
- **D1播种，D2发芽、D3进入幼树是前期体验参考；D4–D7允许多个器官阶段在同一夜间连续完成**。D6首枚水瓜成熟符合预期；玩家采摘、加工并交付首件自产水瓜产品，完成经营教学。所有阶段由真实Growth触发，不按日号延迟或跳过成长。
- **当前开局经营**先用储藏区现有水瓜完成「榨汁→500ml装杯→交给当日客人」；D2增加机器清洁与果壳、果肉残留处理的任务板目标。餐点、药剂、购买、订货及NPC剧情教学属于后续扩展，未定稿前不作为D1–D7必须实现的剧情步骤。
- 白天操作、场景切换与真实经过时间不推进游戏成长；点击结束今日才产生一次1d的结算。

## 2. 随机元素球与7天照顾Buff

| 项目 | 正常游戏日 | 教程期 D1–D7 |
| --- | --- | --- |
| 每日数量 | 6–10枚 | **7–10枚**：7种元素各至少1枚，保底条件优先于常态6枚下限 |
| 单球V | 20–100V | 20–100V，**每种元素至少一枚球≥50V** |
| 每日实际总量目标 | 300–500V | **350–500V**：七维保底共至少350V |
| 每日总量期望 | 约400V | 约400V |
| 元素生成 | 依据水晶球生态七元素总量及外部影响进行条件随机，可重复、可缺某一种 | 优先满足七元素保底，额外球再按随机规则产生 |
| 随机调节 | 球内生态元素比例影响凝聚概率；顾客、劳动、探索、道具等为后续补充来源 | 新手照顾Buff只持续D1–D7；D8起不再有七元素保底 |

- 正常凝聚按**水晶球中各元素总量（Soil＋Eco＋尚存元素球）**计算随机权重：元素越充盈，抽中概率越高，生成所需V仍从相应Eco扣除。**D1–D7每种元素强制抽取一次、每枚至少50V并从Eco扣除**，已有开局储量保证这一保底可行；额外球按正常随机。D8起完全取消保底。具体权重曲线待细化，不改原七维Growth预算。参见[12](12-element-ecosystem.md)。
- 单球20–100V及每日300–500V是两层约束。独立随机抽球的原始总和不一定落在指定区间，生成器需在保留元素随机性的同时满足每日总量区间；具体概率权重、浮动分配算法留待细化。教程期七元素保底同理；不能将最低350V误写成300V。
- D1的1000V为已充盈的Soil状态，无补土道具操作。**水晶球中Soil＋Eco＋尚存元素球的元素V总量上限为10000V**，不计道具与植物；初始Soil为1000V、Eco为3500V，总计4500V。土壤与植物自然蒸发、未收集元素球次晨消散的相应元素量均按**80%回归Eco／20%逸散离开水晶球**记账。原Soil每日保留80%不变；回流80%是蒸发量中的比例。七维初始构成依据开局种子随机比例。
- 原单球固定50V/每日固定8球与「玩家主动逐枚凝聚」不再用于新设计。开店时按生态条件生成元素球，未收集球到次晨不保留，按80%回归生态／20%逸散入账；收集后的实际V进入玩家持有库存，再浇灌到Soil，避免重复生成或复制。持有上限与跨日损耗仍待定。
- 1d策划不再安排随机种子批量模拟，后续先核对具体状态和数值约束是否满足体验曲线。

## 3. 1d 整数化候选基线

**1d = 旧24uh对应的一次完整成长结算**。游戏日参数从体验目标推导，保留旧领域机制；原值仅作迁移参照。

| 参数 | 原24uh等量 | 新1d候选 |
| --- | ---: | ---: |
| Soil 每日保留率 | 0.99^24 ≈ 78.6% | **80%/d** |
| Seed 根系总吸收速率上限 | 48V/d | **70V/d** |
| Seedling 根系总吸收速率上限 | 44.4V/d | **70V/d** |
| Sapling 根系总吸收速率上限 | 384V/d | **400V/d** |
| Sapling Growth 参考预算 B0 | 129.6V/d | **130V/d** |
| 土壤容量（七维合计） | 1000V | **1000V** |
| Reserve 容量（七维合计） | 180V | **180V** |

- 上表的吸收上限、Growth预算都属于**速率上限或参考预算**，不等于当日必定取得的 V/G。实际Root吸收还受土壤总量、RootPreference、七维通道与充盈限流；Reserve→Growth仍使用当前S形函数与逐元素亲和、各器官分流及库存截断。
- 继续保留Tree／叶／生殖的七维Growth账户、V→G转换、亲和继承、叶片竞争、元素反应与成熟后富集的原设计，**不把七元素合并成通用成长能量**。生态与球的V账本按来源／去向处理；果实加工后派生的果汁、果肉、果壳元素值用于性状，可复制平均属性，**不再要求加工产物元素G总量守恒**。
- 先将所有展示/设计公式以 d 表示；引擎是否继续以 Δd=1/24内部积分，交由实现阶段按非线性阈值和04:00出芽事件语义核对。每日合法随机出芽机会只发生一次，不能由积分子步重复触发。

### 成长阈值（仅Seed/Seedling按本轮调整，其余沿用原设计）

| 原阶段事件 | 旧阈值 | 新候选 |
| --- | ---: | ---: |
| Seed → Seedling | Tree累计45G | **50G** |
| Seedling → Sapling | 同一Tree累计90G | **100G** |
| Active Bud → SmallLeaf | Bud20G | **20G** |
| SmallLeaf → LargeLeaf + FlowerBud | 本叶26G | **26G** |
| FlowerBud → Flower | 生殖累计12G | **12G** |
| Flower → GreenFruit | 生殖累计40G | **40G** |
| GreenFruit → MatureFruit | 生殖累计90G | **90G** |

Seed/Seedling的Tree Growth为同一累计账户；达到100G后逐元素转为初始Reserve并建立首芽；Bud 20G、叶26G以及花果生殖累计12/40/90G均保持原设计。生殖账户连续累计，不将阶段门槛相加；单次夜间结算可以连续跨越多个阶段。

## 5. 经营供给与经济学习

- **后续NPC即时购买**：待经营扩展时允许当天购买果子/食材/药材；当前D1已预置首个水瓜，不需要购买才能完成首单。定价、货币与原料清单另案设计。
- **后续NPC提前订货**：作为低成本/计划性供给渠道，价格优势和到货日另案设计，不硬性安排D4必须完成。
- **自产果实**：首果成熟即可采摘并进入生产链，允许早于D7；以首次自产交付完成教程闭环。与外购材料的成本优势、亲和/风味价值以后设计。
- 当前首单只要求现有水瓜→加工→500ml装杯→交单流程，**一果2000ml、四杯各500ml**；果汁、果肉、果壳在拆分时按原果的元素总量平均继承**性状**，**加工产物的元素属性不要求守恒**；果汁体积和各杯实际交付数量仍需准确记账。机器残留与杯子清洗属于后续维护状态，见[11](11-opening-tasks-and-processing.md)。
- 教程完成条件采用「实际采摘、加工并交付首个自产产品」，无需把植物成熟或采摘锁定在D7；D7是经营教学的目标节点。既有委托截止日、奖励与地格成本本轮不定稿。
