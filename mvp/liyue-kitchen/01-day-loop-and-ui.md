# 昼夜节奏、七格水晶球、委托与主界面

## 1. 每天的显式阶段

```
NEW_GAME
  新游戏仅创建一次开局种子，物品栏可直接拖拽播种
DAY_START
  读取上一夜结果 → 出示昨夜简报 → 产生当日订单与免费凝聚额度
DAY_WORK
  玩家不限时接待访客、操纵七格水晶球、仓储、剥壳、榨汁、装杯与探索地图
DAY_CONFIRM
  玩家按下「结束今日」并确认仍在运行的装置和分配
NIGHT_RESOLVE
  按 K uh 积分已有 Growth/反应领域模型，处理订单期限及后续设备生产进度
DAY_START (day + 1)
```

- 白天默认 `Δuh=0`，不在 UI 帧率或鼠标点击时暗中累计世界时间；MVP 剥壳、榨汁、装杯均为即时手动工作台动作，**不占夜间 uh**。后续存在需要时间的设备时再以 K uh 推进。
- `K=24uh/夜` 为首轮测试方案：恰好涵盖一个模型日，可保留模型每日 04:00 的合法芽事件频率。后续若改变 K，必须仍按原模型日事件时间推进，不能将「一晚」直接当成「一次额外抽签」。
- 夜间对 `advanceUH(K)` 做真实阶段/计时事件结算，不用简单乘总产量代替连续 Growth 和状态门槛。数值分步积分方法应由既有领域验证后确定。
- 夜晚不让玩家重复点击，多事件汇总到第二天；结算报告保留可追溯的关键事件（叶形成、反应、成熟、未来设备完成、订单到期），不向玩家默认公开全部七维 Debug 数据。
- 自然世界时间被冻结时，尚未收集的元素球不会在白天因屏幕运行而衰减；进入夜晚后才按原 `0.25uh` 半衰期衰减。可在结束今日前提示有未收集球。
- 允许查看报告与撤销尚未确认的布置；「结束今日」成功后不可无代价回滚到昨夜。存档/读档须单独做平台能力验证。
- U1 先建立可点击主场景。**U2 同时验收**：新游戏物品栏初始化唯一 `Seed`、通过 PixiJS 指针事件拖拽至开放地格播种、每日 N 次元素凝聚与浇灌、结束当天推进 K uh、次晨真实生长与次数重置。种子真实消耗。通过浏览器操作与状态检查验证拖放及夜间结算，不以点击代替拖拽。

## 2. 每日凝聚随机元素

每天有固定 `N` 次免费「凝聚」机会（`N` 初值待数值/交互校准）。每次触发既有规则：随机七元素身份、纯一种元素、球初始固定 50V。生成时不直接灌入土壤，需玩家收集，再将球提供的实际 V 转入选中的洞天地块/土壤或合规容器。

科技可提升每日凝聚额度、批量收集和预设浇灌路线。要避免先提高 N 造成点击负担，再迟迟解锁批量工具。N 的扩张改变每日可用总资源，不改变单球容量、根系吸收上限或生长公式。

## 3. 访客及限时委托

**右侧常驻委托单和探索地图入口**，玩家白天可接收与交付真实订单。前期订单由委托板依据游戏日/探索进度生成，无需 NPC 对话。访客位置保留在左上方，但具体角色、对话、赠物和递单功能排在最后一个开发切片 U9；届时将访客递交的订单写入同一个 `orders` 账本。

MVP **只有两类订单**：
- `aquamelon`：指定数量的完整成熟水瓜，交付消耗真实完整果物件。
- `juice_cup`：指定数量的已装杯水瓜汁，交付消耗真实杯装果汁物件。未装杯果汁不能直接交单。

订单数据包括 `id`、`visitorId`、`acceptedDay`、`dueDay`、`itemKind`、`quantity`、`delivered`、`state`、`rewards`。**截止日包含当日白天**：玩家第 D 天白天仍可交付，按下「结束第 D 天」并进入 D+1 时，未完成订单变为过期，奖励不可领取。期限只按游戏日推进，白天查看、操作或暂停不倒计时。

首单由右侧委托板在前期出现以引导生产，不依赖访客；必须在锁定 K/N 并真实模拟「种子→首果」的随机供给后确定截止日。首单优先完整水瓜，果汁订单在剥壳/榨汁/装杯操作已开放后引入。期限须覆盖合理的首果波动及新手操作余量，不能用未经验证的第 3/5 天固定期限制造必败订单。

订单过期只失去该次交付机会/对应奖励，不造成破产、永久失去剧情种子、科技核心或探索主线。可以通过后续新订单重新获得等效的非唯一资源。MVP 订单一次性整体交付，避免部分交付跨到期日导致物品与奖励歧义；后续如引入部分交付，另行定义账本。

访客可以提供剧情和探索线索，但 P0 不增加要求料理、科研报告等第三种订单类型。订单和探索发现分别持有状态，不能将「逾期」等同「探索失败」。

## 4. 16:9 水晶球柜台的空间合同

```text
┌─────────────────────────────────────────────────────────────────────┐
│   璃月厨房                 第 D 天 / 凝聚 N 次         [结束今日]     │
├───────────────┬───────────────────────────────┬────────────────────┤
│ 访客与对话     │         透明洞天水晶球         │    限时委托单      │
│  来物、线索    │     七个蜂巢排列的种植格        ├────────────────────┤
│               │  每格一棵树 / 地面临时放物品   │    探索地图入口    │
├───────────────┼───────────────────────────────┼────────────────────┤
│  剥壳工作区    │          球下仓储区            │ 榨汁机 / 装杯区    │
│  剥壳工具      │   原果、果肉、果汁、容器等     │  （预留其他机器）   │
└───────────────┴───────────────────────────────┴────────────────────┘
```

- **水晶球是画面中心主视觉**，不再采用泛化的「桌面洞天管理终端」矩形显示器。七个六边形地块为「一中心＋外围六格」，提供固定七个 `plotId`，七格均可见，**初始部分地格锁定，消耗洞天仙力逐步开垦**。已开垦地格最多一棵独立树，独立 `Soil[7]`、`TreeReserve[7]` 与器官状态。初始仅中心一格开放是首轮测试候选，最终依数值校准确定。
- 玩家可以将水瓜、材料、球等**放在洞天水晶球内部地面临时存储**，或移至球正下方仓储区。地面物品 ID 与位置属于真正世界状态，不能当作会被场景刷新清掉的 UI 道具。地面存储不占树种植槽，不能变成额外的土壤/植株。
- 底部两侧为实体工作区：首版左侧剥壳，右侧榨汁及装杯；煮锅、研钵等只预留未来空间，初版不创建无作用的假按钮。
- 右侧两个入口和面板分别展示**委托单**（材料、数量、截止游戏日、奖励、交付状态）与**探索地图**（新发现提示、完成节点、图谱弹层）。图谱展开可覆盖主屏，但关掉后原物品位置和委托状态不变。
- 上方左侧预留访客空间；**U9 之前不挂角色对话脚本，不从访客发放开局种子或订单**。仓储/物品栏负责收纳与排序，球内地面负责随手摆放，两者可互相转移而不克隆物品。
- 样本/物品放置行为通过 `itemId + location(kind,plotId?,x?,y?)` 记录：`inventory`、`ground`、`storage`、`workbench`、`order` 等容器。点击优先级保证地上物品与树重叠时可选中目标；**种子拖拽→落入地格是 U2 必须通过浏览器真实指针操作证明的行为**；鼠标和触摸均须支持合法命中与取消。
- 夜间推进对七格统一使用一个世界时钟 `K uh`，已开垦的各格输入与结算相互独立；锁定格不能种植或吸收。**每天凝聚次数 N 是全洞天共享总额度，不是每格 N 次**。
- 水晶球附近/顶部显示「洞天仙力」当前余额；点击锁定地格显示开垦成本，成功支付后永久开放。访客、订单、种植/采摘真实事件获得仙力，具体奖励去重与收支见 [04-adeptal-energy-and-plots.md](04-adeptal-energy-and-plots.md)。

## 5. 第一段可玩体验（先种植，后访客）

1. 新游戏创建一枚真实水瓜种子到物品栏，七格水晶球显示中心已开放格和外围锁定格；探索地图可以据开局初始物件事件点亮「一粒水瓜种子」。
2. 玩家拖拽物品栏中的水瓜种子到开放地格；真实 seedId 被消耗、目标格出现 Seed/plantId。无须 NPC 对话。
3. 玩家凝聚随机元素球、收集并浇灌；主动结束今天。
4. 次晨出现真实成长反馈；玩家继续生产和采摘，按右侧限时水瓜订单交付。
5. 加工台完成剥壳、榨汁、装杯，交付右侧果汁订单，获得仙力并解锁后续格子、发现和科技。
6. 当核心玩法与完整订单闭环已经实机可玩，最后在预留位置接入访客：对话、携物、新任务线索和仙力互动，沿用同一个订单/物品/成就领域逻辑。

首果及第一张订单截止日要依据 K/N 与真实生长轨迹校准，不能从开场访客是否出现推导。

## 6. UI 交互实施入口

主屏交互对象（物品栏种子、水晶球七格、元素球、仓储、剥壳台、榨汁机、空杯、委托、探索入口、仙力余额、结束今日）使用 React/PixiJS 输入和纯 TypeScript 领域动作；具备状态守卫与可见反馈。访客在 U9 接入；阶段验收见 [05-ui-driven-implementation.md](05-ui-driven-implementation.md)。

## 7. Web 验证

使用浏览器与 Playwright 检查真实指针拖放、遮挡命中、跨尺寸布局、七格数据唯一性、弹层及存档恢复。React 负责 HUD/弹窗，PixiJS 负责场景与交互图形，TypeScript 领域模型是唯一可变游戏状态来源。渲染帧不能推进世界时间。
