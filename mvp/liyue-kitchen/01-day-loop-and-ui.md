# 昼夜节奏、访客与主界面 v0.1

## 1. 每天的显式阶段

```
DAY_START
  读取上一夜结果 → 出示昨夜简报 → 产生当日访客与免费凝聚额度
DAY_WORK
  玩家不限时操作柜台、洞天、仪器、料理、研究与探索地图
DAY_CONFIRM
  玩家按下「结束今日」并确认仍在运行的装置和分配
NIGHT_RESOLVE
  按 K uh 积分已有 Growth/反应领域模型，并结算设备生产进度
DAY_START (day + 1)
```

- 白天默认 `Δuh=0`，不在 UI 帧率或鼠标点击时暗中累计世界时间；动作可以立即转移/加工已有材料，需时间的生产工序在夜间累计进度。
- `K=24uh/夜` 为首轮测试方案：恰好涵盖一个模型日，可保留模型每日 04:00 的合法芽事件频率。后续若改变 K，必须仍按原模型日事件时间推进，不能将「一晚」直接当成「一次额外抽签」。
- 夜间对 `advanceUH(K)` 做真实阶段/计时事件结算，不用简单乘总产量代替连续 Growth 和状态门槛。数值分步积分方法应由既有领域验证后确定。
- 夜晚不让玩家重复点击，多事件汇总到第二天；结算报告保留可追溯的关键事件（叶形成、反应、成熟、设备完成），不向玩家默认公开全部七维 Debug 数据。
- 自然世界时间被冻结时，尚未收集的元素球不会在白天因屏幕运行而衰减；进入夜晚后才按原 `0.25uh` 半衰期衰减。可在结束今日前提示有未收集球。
- 允许查看报告与撤销尚未确认的布置；「结束今日」成功后不可无代价回滚到昨夜。存档/读档须单独做平台能力验证。

## 2. 每日凝聚随机元素

每天有固定 `N` 次免费「凝聚」机会（`N` 初值待数值/交互校准）。每次触发既有规则：随机七元素身份、纯一种元素、球初始固定 50V。生成时不直接灌入土壤，需玩家收集，再将球提供的实际 V 转入选中的洞天地块/土壤或合规容器。

科技可提升每日凝聚额度、批量收集和预设浇灌路线。要避免先提高 N 造成点击负担，再迟迟解锁批量工具。N 的扩张改变每日可用总资源，不改变单球容量、根系吸收上限或生长公式。

## 3. 顾客/仙人的职责

访客在主画面柜台窗口出现。每位访客可持有：
- `dialogue`：剧情文本、线索与世界观；
- `deliveredItems[]`：赠送、借用或交付玩家的实际物品，ID 唯一；
- `request`：可接受/暂存/交付的委托（可无）；
- `hintNodes[]`：引导探索图某一区域，不直接授予未知配方；
- `reward[]`：新种子、配方、设备图纸、研究材料、后续访客等。

委托至少支持：交付指定料理、验证特定生长现象、提供某类样本。委托无需全部在当天完成，除明确剧情事件外没有强制限时与失败惩罚；避免客人排队阻塞自主探索。委托验收读取真实物品 ID、属性与完成事件，而不是仅靠文本按钮。

## 4. 16:9 固定柜台

建议主视觉分三层深度，而非常驻信息分栏：
- **上层访客窗口**：正面角色肖像/立绘，来物和对话；人物真实站在柜台另一侧。
- **中层洞天管理终端**：中央主要可操作窗口，显示洞天土地和植株；可切至研究图谱、种植排布、生产订单；终端视觉表现为璃月机关屏。
- **下层物理工作桌**：可放置材料、器具和委托物品；剥壳、榨汁、烹饪设备为可选中的具体对象。右上角保持当天信息和「结束今日」入口。

窗口仅在使用时覆盖工作台。点击访客给出物品与任务、点击洞天进入布置、点击设备打开操作、点击探索地图放大图谱；同一实际物品的 ID/数量在跨窗口移动后保持连续。避免长期把种植/料理/委托固定成三栏。

**输入优先级**：P0 先验证选择物品→点击目标设备的可靠交互，再验证拖动；不要因平台不支持拖拽中断 P0。错误动作给出原因，不提前执行成功动画。

## 5. 第一段可玩体验（事件驱动，不强制几天完成）

1. 第一位仙家访客带来「水瓜种子」并说出一句引导；真实获得种子，探索地图中央节点「一粒水瓜种子」点亮。
2. 解锁相邻节点：种植、元素供给、第一次新芽；另有一条模糊线索指向尚未知晓的果实变化。
3. 玩家选择地块种植，凝聚随机元素球、收集并浇灌，主动结束今天。
4. 次晨看到生长/阶段变更；根据真实领域事件点亮节点、露出新的探索线索。多晚后收获成熟果。
5. 在桌面加工至少一份真实材料，获得一个料理或果汁并交付访客；解锁加工分支与下一条研究委托。
6. 当玩家已经完成数次同类收集/浇灌动作后，通过图谱和访客线索提示「批量收集」科技，不需要强迫玩家立即研究。

各节点按真实事件完成；首果不能仅由设计假设规定在第 2、3 或 4 天出现，需根据 K/N、元素随机供给与当前成长系统校准。

## 6. 需验证

千星 Lua 可操作的文本/按钮已有局部实机证据；窗口弹层、图层穿透、物品拖放、动态洞天地块、多对象持久化、动画资源、长文本/可缩放图谱及正式存档能力必须逐项真实验证。编辑器静态放置资产，Lua 拥有权威状态、输入和计算。
