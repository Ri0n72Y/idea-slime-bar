# 璃月厨房：还得自己种 — MVP

## 定位

单机 2D 种植、生产与发现游戏。玩家在璃月厨房操作七格洞天水晶球，培养具有七元素特性的水瓜，收获并加工成果汁，完成限时委托，积累洞天仙力，探索新知识和技术。访客与剧情在核心循环完成后接入。

主线：**发现 → 验证 → 完成探索节点 → 解锁新能力**。科技在玩家经历对应劳动后减少重复操作。

## 技术方案

- **React + TypeScript + Vite**：程序入口、HUD、菜单、委托、仓储和常规表单/面板。
- **PixiJS 8（可使用 @pixi/react）**：水晶球、七格地块、植物、物件拖放、动画和二维场景。统一使用 PixiJS 的渲染器，无需叠加另一套 Canvas 2D 绘制器。
- **纯 TypeScript 游戏领域层**：世界状态、物品唯一 ID、七元素 V/G、Growth、生长、反应、昼夜结算、经济、委托、事件及探索。领域代码不依赖 React/PixiJS，也不直接修改 DOM。
- **浏览器持久化与测试**：本地存档（优先 IndexedDB，按实际需求实现）、可复现随机种子、Playwright 实际浏览器交互与截图。只有通过实际输入和状态核对才算功能完成。
- **Tauri v2**：Web 玩法稳定后再接入桌面和移动端打包。MVP 首阶段不增加 Rust 业务后端或平台专属实现。

新游戏代码独立放在 `packages/liyue-kitchen/`，不直接沿用仓库内其他实验性 Web 界面。当前目录是设计合同，不代表功能已经实现。

## 核心规则

- 新游戏物品栏直接生成**一枚**真实水瓜种子；U2 使用鼠标或触摸拖放到开放地格播种。
- 水晶球固定**中心一格＋外围六格**。初期中心格开放，其他格需花费洞天仙力逐步解锁；每格独立管理 Soil、Reserve 和植株。
- 白天交互不推进 Growth；玩家明确「结束今日」后一次推进 `K uh`，次晨展示真实成长与事件结果。初始 `K=24` 是待校准候选值。
- 每日全洞天共享 `N` 次纯元素球凝聚，单球初始 50V；次数与输入不随渲染帧率变化。
- 加工链：**完整水瓜 → 剥壳 → 果肉 → 榨汁 → 原汁 → 装杯果汁**。限时委托仅为完整水瓜与杯装果汁两类。
- 探索进度依据真实事件完成。洞天仙力由有效种植、采摘、委托、发现和后期访客互动产生，按来源去重，用于开垦和技术升级。

七元素、Growth、反应及感官数值合同以 `../aquamelon-kitchen/` 的对应领域规则为参考；迁移时逐项复核既定规则，不自行修改数值。

## UI 和开发顺序

横屏以 **16:9** 为主，适配 PC、触摸设备与不同像素密度。React DOM 负责菜单/HUD/功能面板；PixiJS 负责中心二维洞天、水晶球与操作对象，避免两套系统重复处理同一物件。

**U1** 完成可点击主场景、七个地格和区域边框；**U2** 在一个可玩切片内完成种子拖拽、元素凝聚/浇灌、结束今日、次晨生长；**U3～U8** 顺序打通采摘、加工、订单、仙力、探索/技术与无访客完整循环；**U9** 最后接入访客。

验收、输入与状态合同见 [05-ui-driven-implementation.md](05-ui-driven-implementation.md)。
