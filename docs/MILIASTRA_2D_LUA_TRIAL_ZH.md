# Aquamelon Kitchen · 千星 Lua 文字试玩（独立探索支线）

## 定位和边界

本支线与现有 Web 版本、千星正式 F1 PR #9 **并列，不覆盖、不合并它们的运行状态**。源文件：
- `packages/genshin/src/aquamelon-kitchen/2d/WK_TextTrial.lua`（游戏状态与按钮事件）。

**UI 由用户在千星编辑器里静态布置。** Lua 不控制控件坐标、尺寸、锚点或字号。先前的 `WK_TextTrialLayout.lua` 应从已经配置的关卡中取消挂载。

这是**单机、客户端内存试玩**：没有服务器节点图、信号、永久存档、离线回放、多人同步。数据仅存在当前 Lua 脚本运行内；关卡重进会重置。正式千星版仍要让服务器掌握权威状态，并从 Web 的 canonical domain / MVP 设计迁移完整 Growth Tick，不能把这个局部 Lua 测试计算作为权威实现。

**本次可试玩：**铺土、播种、七元素选择、向土壤临时直接加入 10 单位、每 10 秒自动推进一次 Tick、手动前进 1 / 10 Tick、查看 Soil / Growth / Reserve、重置。土壤溢出同比压到 100、0.99 自然保留、根系单元素 cap/总 6 cap、Seed 45→Seedling 90→Sapling 阈值与 Web v0 的试验系数一致。**Sapling 只收集 Reserve**；不自创树苗代谢、芽叶、花果与加工计算。`AddElement` 是试玩辅助按钮，**不等价于** Web 的元素球生命周期/捕获动作。

不要把 Lua 游戏内的 `NextTick` 与 PR #9 的服务器 `WK_Debug_NextTick` 混用；**这两个是不同测试世界**。当前 F1 的信号仍是未执行 F2 的回执。

## 开局直接进入 2D 鼠标操作模式（官方配置；无需 Lua 抢输入）

**适用：PC 使用鼠标直接点击本游戏 8 个按钮；WASD 不控制背后的原神角色。** 这是平台的 **玩家模板 + 职业 + 单位状态 + 主屏布局** 配置，不是 `WK_TextTrial.lua` 的代码功能。官方文档确认各入口存在，但**鼠标解锁/镜头是否完全无响应仍需千星实机确认**；不要在 Lua 里猜测不存在的“LockCursor(false)”或键盘全局屏蔽 API。

1. **玩家模板：常驻光标。** 打开「战斗预设 → 玩家 → 该试玩玩家生效的玩家模板 → 玩家编辑 → 光标配置」：
   - **光标常驻 = 开启**。官方将其定义为玩家的常驻光标显示，尤其适合屏幕点击玩法。
   - **点击可穿透 UI 控件 = 关闭**，使点击游戏按钮不继续选中/击中背后的场景。
   - `可点击层级` 与 `光标最多可选目标数` 面向 **3D 场景实体选取**。本版只有客户端预设按钮，不需要设置光标碰撞盒，也不要额外实现实体点选。
   - 核实玩家模板的 **生效目标** 确实包含本次试玩玩家，避免只修改一个没有应用的模板。
2. **新建禁止角色移动的单位状态。** 「战斗预设 → 单位状态 → 新建状态」，建议命名 `WK_2D_NoMovement`。启用**无限持续时间**，在效果池里选 **`角色禁止移动`**，作用对象为 **角色**（不是玩家实体）。官方定义该效果可禁止方向键/摇杆驱动角色移动。**勿选近似名字 `禁止移动`**：后者是针对造物的常规移动限制。
3. **为专用职业配上这个状态。** 「战斗预设 → 职业 → 新建职业」，如 `WK_2D_UI`：
   - 在职业的 **「单位状态」** 配置加入 `WK_2D_NoMovement`；官方说明切换到职业时会把职业配置的状态加到**对应角色**身上。
   - 将「允许跳跃 / 允许冲刺 / 允许攀爬 / 允许滑翔」分别关闭，防止 Space、Shift 等继续触发 3D 行为。职业选项与状态可互补，不能把“仅禁 WASD”误写成禁止所有动作。
   - **选择布局** = 包含你已设置的客户端控件容器的默认布局。**选择镜头** = 一个当前版本中可确认可用的静止背景镜头模板；官方支持 **2.5D 镜头**。对纯文字 UI，角色、场景不参与交互，优先选无遮挡、画面稳定的背景视角，镜头的水平/俯仰可操作范围及缩放范围**只在编辑器支持并经过实机核对的条件下**才可收紧；官方不保证“角色禁止移动”会锁定镜头转动。
4. **把职业设成玩家初始职业。** 回到第 1 步的**玩家模板 → 基础信息 → 初始职业**，选择 `WK_2D_UI`。它是关键的**开局生效**步骤；如果仅创建职业而未被指定初始职业，仍可能以传统 3D 职业开局。
5. **关卡布局和手机端适配。** 「界面控件组管理 → 界面布局」确认该职业的布局实际应用到玩家，并且客户端控件容器 **初始可见/激活**。可在布局中将不需要的原生**移动摇杆、技能区等固有控件**设为初始不可见（以编辑器允许的设置为准；不要删除固有控件）。为真正的视觉 2D，可将一张不透明客户端背景图片铺满 UI 画布并排在文本与按钮下方；这是**可选的后续界面资产**，当前 10 子控件的最小试玩不需要它。移动端主要用触屏点击 UI，官方“光标点击释放技能”用于移动端额外的**场景点选技能逻辑**，本版纯 UI 按钮不需创建该技能。
6. **保存并重新开始试玩**，不要只在正在运行的试玩内修改玩家模板/职业：开局职业与默认布局是在进入关卡时应用的。验收按下面的表操作。

| 实机检查项 | 预期结果 | 失败时先检查 |
| --- | --- | --- |
| PC 开始试玩，无需按 Alt / ESC | 鼠标光标直接可见，可移动至各按钮 | 玩家模板是否生效；`光标常驻` 是否打开 |
| 按 WASD、方向键、手柄左摇杆 | **角色位置不变化** | 职业的无限单位状态是否真正加在角色上；效果名是否为 `角色禁止移动` |

| 鼠标移动、拖拽、滚轮 | UI 可持续点击；背景镜头**不能影响试玩** | 先检查镜头模板及范围；是否仍存在默认鼠标镜头控制，记录真机现象 |
| 点击「铺土」「播种」「+1Tick」 | 只改变 Lua 试玩状态，不穿透触发 3D 场景 | 光标是否穿透 UI、客户端按钮是否可交互、玩法 Lua 映射是否已挂载 |
| PC 横屏 / 手机竖屏 | 一屏显示 9 行状态、最多 2 行日志、8 按钮 | 职业默认布局、容器可见/激活、根控件是否铺满画布 |

## 官方编辑器最小接入步骤

1. 在测试关卡选择当前试玩角色**实际应用的界面布局**：界面控件组管理 → 界面布局 → 添加「客户端控件容器」，确保容器**初始可见、激活**。
2. 选中客户端控件容器 → 画布设置 → 前往编辑。**保持你现有的根控件名称**，无须修改为 `WK_TextTrialRoot` 或 `WK_TextTrailRoot`。脚本会读取其实际挂载宿主 `script.object`。
3. 继续使用自己已布置好的 `Snapshot`（状态）与 `History`（最近两条游戏记录）文字控件；**无须更换或移动**。脚本只更新 `.text`。TextBox 和 TextWindow 都支持该字段，是否滚动由你在编辑器中静态决定。
4. 同层添加以下 **8 个客户端预设按钮**，名称必须精确匹配（大小写敏感）。显示文字可自由写：
   - `PlaceSoil`（铺土）、`PlantSeed`（播种）、`ElementPrev`（上个元素）、`ElementNext`（下个元素）
   - `AddElement`（向土壤加所选元素 10）、`NextTick`（推进 1 Tick）、`Next10Ticks`（快进 10 Tick）、`Reset`（重置）
5. **完全保留已有静态布局**：不规定根控件铺满画布，不修改坐标、尺寸、锚点、字号、按钮显示文字。内部根控件可以保留你已有的名称；只需要从**脚本实际挂载的客户端控件**中查得到 `Snapshot`、`History` 以及 8 个按钮。
6. 千星沙箱 → 客户端脚本资源管理器 → 建立或保留**一个** `WK_TextTrial.lua` 脚本映射，不需要 `.gia`。
7. 选中**容器内部的实际客户端根控件（即含有 10 个游戏控件的那个节点）** →「脚本」→挂载唯一 `WK_TextTrial.lua`。不要把外层服务器「客户端控件容器」名称当作脚本宿主。若旧的 `WK_TextTrialLayout.lua` 还挂着，**先取消该映射的挂载**，否则会继续移动 UI。保存后重进试玩。
8. 若 UI 不响应，检查生效布局、容器是否激活、根名称与单个 Lua 映射。若 UI 自己移动/修改字号，检查并取消旧布局脚本映射。按钮缺失时核对控件名称与子节点路径。

## 实机反馈：根控件名称查找失败的处理

旧源码使用 `game.FindClientUIRoot('WK_TextTrialRoot')`，最近一笔修复尝试改为 `WK_TextTrailRoot`，这两个拼写不同；但**仅靠硬编码名称查找仍容易误认外层客户端控件容器和实际运行时 UI 根节点**。

当前源码改用官方 `script.object`：**直接把 Lua 挂载到包含 `Snapshot`、`History` 和 8 个按钮的客户端根控件**，启动时获取该宿主对象并在千星沙箱客户端脚本日志打印 `WK_TextTrial attached UI: <name>`。**无需重命名或重新排列任何 UI**；`WK_TextTrialRoot` 或 `WK_TextTrailRoot` 只是你编辑器中已有的控件名字，不再被 Lua 用于寻找运行时根。

若出现 `script.object is nil`，检查当前 Lua 映射是否确实挂载到了客户端控件而非只创建了脚本文件。若出现 `missing Snapshot / History under ...`，看日志中的 `attached UI` 名称是否为你真正安排按钮的根控件，并调用 `game.PrintClientUITree()` 打印层级；本版 `root:FindChild(name)` 仍要求从脚本宿主处查得到这些控件。不要通过修改 UI 坐标来修复控件查找问题。

**保存脚本、关卡并重新进入试玩**后，再查看最新日志。更改源码不会自动让已加载的客户端脚本重新执行。
## 千星实机验证：客户端 Lua 与静态 UI 接入通过

本次依据创作者在**千星奇域实际试玩**中的直接反馈，而非模拟器推断：

- 原来的 `game.PrintClientUITree()` 输出 `[UITree] Roots: 0`，而编辑器中手动布置的 UI **正常显示**；该现象不代表 UI 未生成。
- 通过脚本宿主探针获得 `[HOST] WK_TextTrialRoot ClientUIContainerControl`，说明挂载的客户端脚本取得了预期运行时宿主。
- 创作者进一步确认：**Lua 已成功加载并控制 UI 控件，最小接入测试完成。** 因此客户端文字试玩可以继续沿 `script.object` → `root:FindChild(name)` 路线开发。
- 运行时 UI 坐标、尺寸、字号、锚点与静态控件排布仍完全由创作者在编辑器中维护；脚本只写文本和绑定交互事件。

**验收范围：通过**——客户端 Lua 加载、运行时宿主对象可读、能够控制已显示的静态客户端 UI。**尚未按完整操作序列验证**——全部八个按钮的每项行为、Seed/Seedling/Sapling 生长数值、自动/手动 Tick 一致性、离线回放、长期保存或多人权威状态。后者不可由本次 UI 验收外推。`game.FindClientUIRoot` / `GetClientUIRoots` 仍可能受注册时机或平台行为影响；保留实机症状记录，不将 `Roots: 0` 武断归为引擎 Bug。

**下一步**：在现有静态 UI 上按操作验收清单逐步确认事件与 Tick，并以现有 Web domain 的规则为对照；后续才逐步增加完整器官生长与像素表现。本支线不修改 F1 服务器权威路径。

## 静态 UI 约定与调试日志

本支线不再提供运行时 UI 排布脚本。**页面布局完全由用户在千星编辑器里静态设置**；Lua 仅更新 `Snapshot.text` / `History.text` 并监听按钮。状态文本最多 9 行，`History` 最多显示 2 条游戏事件；它们的长宽、位置、锚点、字号和是否可滚动均不由脚本设置。

### 查看 Lua print 和运行错误

1. 在 **千星沙箱 → 顶部「窗口」→「日志」** 打开日志窗口。
2. 在日志窗口**勾选「客户端脚本」**，并点击**「确认选择」**；再开始关卡试玩。
3. `print(...)` 写普通日志；`printerr(...)` 写错误日志（只打印，不抛异常、不阻断运行）。如有报错，**双击日志条目**查看详细错误信息。
4. `WK_TextTrial.lua` 进入 `OnStart()` 时打印 `WK_TextTrial OnStart` 及 `WK_TextTrial attached UI: <控件名>`。未挂载宿主、找不到文字控件或按钮时会 `printerr(...)`，并在根控件出错时打印客户端 UI 树。没有日志时检查客户端脚本筛选是否确认、脚本映射是否真正挂载、容器是否激活。
5. 如果循环调用等问题导致卡死、通常日志无法显示，官方还提供本地 `ErrorLog.txt`：位置与**客户端脚本的储存路径相同**，仅在出现普通日志无法报告的错误时创建。

`History` 是玩家看到的**游戏内事件摘要**，不是调试日志控制台；服务器「节点图日志」与**客户端脚本日志**不是同一类信息。

官方参考：[客户端脚本·日志功能](https://act.mihoyo.com/ys/ugc/tutorial/detail/mhbgxf0nynww)、[客户端控件 API](https://act.mihoyo.com/ys/ugc/tutorial/detail/mhtakr07vej4)、[千星沙箱](https://act.mihoyo.com/ys/ugc/tutorial/detail/mho777i0ga90)。

这份试玩不涉及 `.gia` 生成，也**不要求加载**当前 F1 Soil / Tree 节点图；刻意降低首次实机操作成本。

## 操作验证清单

1. 启动：显示「空地、尚未播种」，按钮不报错。
2. 先尝试播种与加元素，状态不变；铺土后可以播种，重复铺土/播种不应复制实体。
3. 默认水元素，点击加元素一次，Soil Hydro 为 10，Tree Growth 仍 0（尚未 Tick）。
4. 点击 `NextTick`：Tick +1，土壤先保留 99%、之后吸收；水元素 Growth 开始增加（Seed/Seedling）。
5. 重复补充元素并用 `Next10Ticks` 快进：Seed Growth 达 45 转 Seedling，清空该阶段 Growth 并固化有效亲和；再达 90 进入 Sapling。
6. Sapling 阶段：后续吸收增加 Reserve；**不会出现未实现的叶片或成熟水瓜**。
7. `Reset` 返回初始状态；退出关卡后重进数据重新初始化。日志检查客户端是否有运行时错误。
8. 在你自己布置的静态 UI 中验收：状态最多 9 行、游戏记录最多 2 条、八个按钮可点击。**脚本不调整页面布局**。若显示溢出，由你直接编辑 UI 资源；模拟器通过不等于千星实机通过。
