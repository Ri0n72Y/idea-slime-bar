> Art Lead 设计稿，2026-11-20。**候选尺寸，未做当前 Production 浏览器视觉验收；非 Coder 实现完成证明。**
>
> 约束来源：[用户确认的工坊优先双场景](https://github.com/Ri0n72Y/idea-slime-bar/blob/design/liyue-daily-growth-workshop-1d/mvp/liyue-kitchen/10-workshop-first-layout.md)、[工程 #69](https://github.com/Ri0n72Y/idea-slime-bar/issues/69)、[美术工作 #62](https://github.com/Ri0n72Y/idea-slime-bar/issues/62)。本轮新要求：**把视觉重心适当转回种植培养，缩小 NPC 窗口，扩大可识别的球形水晶球与实时植物缩略图，缩减引导区。保留工坊优先＋独立园地，不引入租金经营压力。**

## 2. 玩家体验定位

- **主循环**：看植物变化 → 取养分/照料 → 主动结束今日 → 观察阶段变化 → 采摘 → 加工与交付。经营、NPC 与委托提供方向和反馈，**无租金/罚款式催促**。
- 借鉴《深空当铺》（Probably Stolen）的**室内柜台、实体设备、空间内纸条、物品自然摆放、按需打开详情**。不沿用其顾客主导、巨额经济压力与高密度交易状态。
- 默认工坊保留为玩家返回的主空间；可**从显眼的真实水晶球进入独立园地**。独立园地承担播种、具体植物/果实交互；工坊中的球体作为同一真实世界的**实时概览缩略图**，不是一件静态装饰。
- 不恢复旧版“整个屏幕七格六边形”；未解锁外格在视觉上隐藏，已解锁格依据实际世界数据出现。

## 3. 1600×900 布局预算

以上限 1600×900 作为参考；比例可按视觉验收修订，**不要把下表当成固定像素 CSS**。

| 层级/区域 | 建议范围 | 表现/常驻内容 |
| --- | --- | --- |
| 顶部细信息牌 | **0–62px（约 7% 高）** | 日期、仙力、凝聚进度、存档/结束今日。尽量只留必要项 |
| 工坊主体 | **62–865px（约 89% 高）** | 一个连贯的璃月木质工作间，物件相邻，避免独立仪表盘边框 |
| 底部反馈 | **865–900px（约 4% 高）** | 一行状态反馈＋存档状态＋小型“?”入口，不给帮助文占用半屏宽 |
| 左侧货架 | **x=0–270（约 17% 宽）** | 实际持有材料、收纳、元素存储，可从上部直接拖到台面 |
| 主要水晶球 | **x=270–930（约 41% 宽）；y≈80–635** | **直径约 500–540px 的完整圆形球体**，能看到真实生长的微型树/果实、球内土地与少量高光；底座有“进入园地”反馈 |
| NPC 接客窗口 | **x=930–1240（约 19% 宽）；可见窗高约 220–260px** | 小型服务窗、立绘/名字、必要对话；无访客时变为真实窗洞，不留大块空面板 |
| 右侧设备与墙面 | **x=1240–1600（约 23% 宽）** | 纵向机器、加工材料、挂纸；剥壳与榨汁装杯依然可直接操作 |
| 前景工作台 | **y≈635–865（约 230px，高度约 26%）** | 左收纳/元素格，中物品拖放与工作台，靠 NPC 的委托交付区；与两侧设备自然接续 |

建议使用“背景整图＋分层的相对定位/网格锚点”，而非把以上数值重新画成十几个带边框的独立网页卡片。柜体木板、窗口、纸条、抽屉可以承担视觉分隔作用。空间优先级为**球内培育现状 > 当前可执行动作 > 委托/访客 > 历史/研究信息**。

小视口 `1280×720`：按同一逻辑缩放但不以纯 CSS `transform:scale` 掩盖命中问题。球直径目标约 400–430px；触控主要目标采用可实际点击的命中区；文案超长进入抽屉/纸条弹层，避免把字号压到不可读。

## 4. 水晶球缩略图合同（本轮最高优先级）

**工坊的水晶球必须显示真实的植物生长。** 将现有 `garden-portal` 改为一个可识别、长宽相等的圆形透明洞天球，底座占位；画球应使用 `aspect-ratio: 1 / 1` 或等轴绘制，不得拉伸成椭圆。

真实内容取自现有 `GameState.plots` / `plant` / `leaves[].fruit`：

| 真实状态 | 工坊球中显示 | 园地显示 |
| --- | --- | --- |
| 新开局：P01 空、唯一种子在物品栏 | 空土壤＋安静的洞天环境，**不能预画已播种树** | 允许拖种子播种 |
| `Seed` / `Seedling` | 破土、小芽的清晰缩略符号 | 对应植株生长阶段和合法操作 |
| `Sapling`＋叶片 | 可分辨的主干、稀疏不对称枝叶 | 可观察实际叶片器官 |
| `FlowerBud` / `Flower` / `GreenFruit` | 对应微型花蕾/花/青果，保证主轮廓可辨 | 同一花果状态，无虚假成果 |
| `MatureFruit` | 成熟水瓜可视点与必要的“可采摘”提示 | 点击真实 `leafId` 执行采摘 |
| P02–P07 未开垦 | **完全不显示外围六角地块** | 使用球座或简洁“开垦”入口提示可扩展性 |
| 多格已开 | 对应地格/微型树逐步显示；植物可越出六边形边缘 | 保留七独立地格/植物状态，不克隆植株 |

工坊缩略图**只读取**真实领域状态；不可把挂果数渲染成可领取的背包果实。工坊点击球可沿用 `enter-garden` 进入园地；**完整播种/采摘仍在独立园地**，避免违反已确认的两场景合同。默认工坊的种子/库存与园地仍使用既有合法物品转移，不生成第二个 `GameState`。

**程序实施风险**：现有 `CrystalScene` 是带 Pixi 输入的交互场景，不应不加区分地在工坊预览与园地同时挂两套可写入的命中注册。可为工坊使用只读预览渲染器，并复用同一状态映射/视觉资产；园地保持唯一主动事件处理。现有 `plotGeometry` 的 `radius<=70` 上限应按可用舞台高度和期望球直径重估，完整园地中的球体也要真正占据主要视野。

## 5. NPC、订单和机器

**NPC**：默认不占中央整列。服务窗宽约 19% 全屏；来客时显示小头像、2 行左右短对话和最必要操作，更多选项可从服务窗弹出纸质面板。无访客时保留窗洞、环境，不显示巨大的“尚无访客”空状态卡。已有 `visitorChoices` / `TALK_VISITOR`、重复奖励守卫保持不变。

**委托**：以贴在柜台附近的纸条/夹板显示一条主要任务的种类、剩余游戏日、数量和可交付状态；多单由纸张堆叠或展开列表承载。候选交付物、错误材料提示及实际 `itemId` 选择仍须可以打开；省去持续堆叠多段解释文案。委托逾期仍依游戏日计算，不增加实时倒计时压力。

**加工/收纳**：左侧材料格与底部柜台稳定可达；右侧机具垂直排列，保留 `peel`、`juice`、`cup` 原命令与有效拖放区域。装杯机自带杯，不能增加空杯道具。物品栏、仓储、地面、工作台仍按实际 `itemId/location` 唯一实例渲染。

**探索/日记**：默认缩为墙上的研究书本或挂图入口，只有新发现时短暂提示，不长期占用一整块高优先级空间。

## 6. 引导、反馈与文字密度

目前 `showGuidance` 默认展开、跨重启记忆，底栏 `.experience-hint` 占至多 49% 宽。建议改成：

- 普通游玩默认**小型可点的“？”/手札入口**，不长期保留半宽度文字区。第一次遇见播种/收集/浇灌时，在**对应实际物体旁**显示一条简短操作提示；完成即消退，可主动重新打开。
- 使用既有 `nextActionHint(state)` 的状态驱动逻辑作建议数据，不制造自动操作、强制路线或新任务。新手可以自主学习操作并获得反馈。
- 错误拖放、订单材料不合格、无法采摘等仍给出**具体原因与纠正动作**；优先在相关对象附近展示，底栏可保留一行状态。
- 底部状态栏目标 **3–4% 高**；可选长文本通过按需浮层/手札展示，不为了节省空间把字缩到难读。显示/隐藏不遮盖球体采摘位置及工作台拖放目标。

## 7. 可实现性与验收

| 责任角色 | 本轮交付 |
| --- | --- |
| Art Lead | 本方案、视觉焦点与布局阈值、审美验收；不画大量零件 |
| Coder | 以现有 `App.tsx` / `workshop.css` / `experience.css` / Pixi 组件为基础重排；实现真实状态驱动球体预览；保留单一领域状态和现有 testid；代码与浏览器回归 |
| Painter / Technical Artist | **目前仍暂停正式美术线**；日后由画师先给出完整工坊整图，技美按整图拆件，不影响本轮基础 UI 调整 |
| Reviewer | 独立源码、交互守卫与 CI 审查 |
| Experience QA | 在真实部署验证视觉权重、点击/拖放、引导和两分辨率下的遮挡与认知 |

实现验收要求：

1. 工坊首屏存在直径清晰、比例正确的实体水晶球，能反映**新开局空地 → 实际播种 → 芽/树/挂果 → 已采摘**的状态变化；没有凭空出现的植物或物品。
2. NPC 窗口常驻可见面积显著小于原中央大列，缺席时不留下大空白；访客与委托的有效操作仍可发现和完成。
3. 工坊球入口 → 园地 → 工坊完整回切；园地保留播种、收元素、浇灌、采摘、地面存放及仓储转移。 `GameState`、`itemId`、`plotId`、订单和 Growth 规则不变。
4. 底栏为单行、小面积反馈，下一步提示不占固定半宽空间；所有错误仍可理解并可恢复，提示入口始终可重新打开。
5. 1600×900 桌面与 1280×720 模拟触摸查看真实截图，检查圆形不变形、文字可读、动作按钮/拖放合法命中、弹层和存档状态。
6. 真实浏览器/Production 视觉验收前，保持状态为 **设计已提出/实现未验收**，不可从此文推断工程已完成。
