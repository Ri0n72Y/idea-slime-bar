## 1. 当前实现事实与冲突

- `packages/liyue-kitchen/src/App.tsx` 默认 `scene="workshop"`，园地为独立 `scene="garden"`，二者使用同一个 `GameState`。
- `src/workshop.css` 的工坊分区是 `25% 49% 26%`；左侧分区的上 30% 是 `garden-entry`，中央 49% 又按 `35% 37% 28%` 垂直分配访客、委托、库存，右列按 `50% 50%` 摆两类机器。
- 当前工坊 `garden-portal` 用 `◉` 和文字入口代表水晶球，`garden-overview` 只列已开垦、待收集球和挂果数量；**没有实时生长植物的视觉预览**。
- `src/scene/CrystalScene.tsx` 的园地使用几何六边格、🌱与圆形果实占位；`plotGeometry.ts` 的六边形半径硬上限为 70px。完整园地另行审查真正球体比例，**不要把园地球的大小限制套用到工坊小设备**。
- `src/experience.css` 的下一步提示最多占底部栏 49% 宽度；`showGuidance` 默认展开并持久保存显示选择；底栏高度现为 7%。

以上依据当前 `main` 源码；已检查的旧版 Playwright 截图不对应这次双场景 Production。新布局需要后续真实浏览器截图与交互验收。

## 2. 空间原则

**一间完整的室内工作坊，一个外向接客窗口，一个靠前可操作的柜台。** 在画面里用墙面、窗框、货架、机器、桌面和收纳格划分功能，避免将其重新做成互不关联的网页仪表盘。

- **后景从左到右**：左侧**设备级水晶球**、中间**接客窗口（约 30% 屏宽）**、右侧**货架/陈列柜**。窗口是唯一可见户外璃月景色的区域，其余区域为封闭屋内墙面。
- **前景**：贯通式工作柜台，实际拖放台面、剥壳机、榨汁装杯机、物品栏/仓储/元素存放格均在前景，可在营业中直接操作；实际存货不能只陈列在后景。
- **信息层**：日数/仙力/结束今日小型顶牌；简短状态反馈小型底边；订单是靠近接客区/柜台的实体纸条，研究与日记放到墙面书卷/手札入口。
- **水晶球**：只读概览呈现实际植物成长、挂果和已解锁地格，点击进入独立园地；不在工坊球上再造一套可执行播种/采摘/浇灌输入。
- 主循环关注培育与加工带来的进展和自由整理，不把 NPC 面板持续充满屏幕，不照搬《深空当铺》的租金/处罚与强制倒计时。

## 3. 1600×900 空间预算（设计提案）

下述为**画面中的自然空间占比**，不能直接把三个区域实现为三块有边框的大面板。

| 区域 | 推荐位置和尺度 | 常驻物件及用途 |
| --- | --- | --- |
| 顶部小型状态牌 | y≈0–60px，约 6–7% 高 | 日期、仙力、收集数量、存档和关店/结束今日 |
| 后景墙面和接客区域 | y≈60–535px | 球设备、窗、墙面货架；区域有重叠景深，不画齐平卡片 |
| **左侧水晶球设备** | 后景 x≈0–480px（约 30% 区域），**圆球直径建议 280–330px** | 在适当台座上展示真实植物缩略图；作为园地入口，视觉级别低于柜台整体 |
| **接客窗口** | 后景 x≈480–960px，**约 30% 全屏宽（480px）** | 窗外璃月景色、来客立绘、简要姓名对话；窗边委托纸 |
| **右侧货架** | 后景 x≈960–1600px，约 40% 区域 | 展示型置物架、卷轴、书本、样品；必要的可点击抽屉入口可延伸到前景 |
| **前景工作柜台** | y≈510–865px，约 39% 高；覆盖几乎全屏宽 | 真实存物格、材料托盘、物品拖放桌面、剥壳设备、榨汁装杯设备、交单位置 |
| 底部单行反馈 | y≈865–900px，约 4% 高 | 短状态反馈、存档状态、可重开的“帮助”入口 |

接客窗口 **30%** 指窗框占据的**屏幕宽度**，不是页面高度，也不是让整个宽度变成长期展开的对话列表。窗口应有自然景物、人物出现/离开状态；访客离开时保留窗景。

实际存储**全部落在前景**：后景货架上的瓶罐、卷轴和装饰可以构成环境，但 `inventory`、`storage`、`heldElements` 的可操作储位必须位于前景（或从前景开启的实物柜门/抽屉），不能被后景的装饰货架偷换。

在 `1280×720` 下，优先保持窗占比、工作台操作空间和球形长宽比。可将球缩至约 225–265px，保持球内植物轮廓可辨；真实可点击区域和物品拖放目标应按实际 viewport 重算，不能只缩图片。

## 4. 工坊水晶球预览与园地合同

- 工坊球保持 **1:1 真圆**，有透明球壳、有限高光、底座和可发现的“进入园地”操作；不要把水晶球放到中央变成画面主角。
- 植物缩略预览从现有 `GameState.plots[plotId].plant` / `leaves[].fruit` 读取；工坊球展示真实的中央幼苗/小树，以及已开垦的外围植物。前期未开垦外围六格不画六边形。
- 新开局 `P01` 为空、物品栏只有种子时，球内显示空土壤。玩家播种后才出现 `Seed` / `Seedling` / `Sapling` 相应轮廓。花蕾、花、青果、成熟果只展示真实存在的器官，成熟果可用小标记提示，但**预览不额外生成可领取果实**。
- 工坊小球里只需看出“在长什么、有没有挂果、哪里已解锁”，精细器官操作与采摘留给独立园地。园地内须另外保证圆球比例和实际输入命中，植物可以越过俯视六角地块边缘。
- 工坊可使用与园地一致的数据映射，但应独立采用 **只读渲染层**；现有 Pixi `CrystalScene` 的主动输入与 `onRegisterDropTarget` 不得在预览中重复注册为第二个可写世界。

## 5. 柜台操作、NPC、委托与文字

- **前景从实体工序组织**：物品存放 → 可拖放工作桌 → 加工机具 → 成品与交付。允许左右机器根据审美和鼠标拖动距离调整，但全部属于同一连续前景层，不得重新放回背景右列。
- 剥壳、榨汁、装杯仍映射当前 `workbench/peel` 与 `workbench/juice`，只绘制确实存在的动作；装杯机自带杯，无可取用的独立空杯。
- 物品栏、仓储、地面、工作台通过真实 `itemId + location` 转移，同一物品不得跨场景复制。为关键拖放区域提供可见的可放置反馈。
- 访客在窗口中显示小立绘、短对话及必须的选项；更多对话在窗口边上的纸条/弹层展开，无访客则完整展现窗外景色。
- 委托单位于接客窗口边缘或柜台上，展示紧要的数量、截止游戏日、奖励与状态。多委托按需展开；选错材料的拒绝理由与合格材料选择仍可达。
- 探索、日记、详细植物研究作为书本/卷轴入口，只有当前需要时展开，不能在默认工作区挤占柜台。

## 6. 引导与反馈

- 取消默认长期展开、占底栏一半宽度的完整引导句；普通玩家只见小型 “?” / 手札入口。首次遇到具体动作时在对应设备/种子/物品附近出现一条短提示，完成即退，玩家可再次打开全文说明。
- 继续复用现有 `nextActionHint(state)`，不强制自动操作，不创造新教程资源，也不隐藏有效错误反馈。
- 非法拖放、错误交单、不可采摘等信息在相关物件附近或底部单行反馈明确说明原因及纠正动作；重要信息不能因收起帮助而丢失。
- 底栏目标 3–4% 高；弹出提示时不挡住桌面拖放区及窗口对话操作。

## 7. 设计与验收边界

| 角色 | 交付与权限 |
| --- | --- |
| Art Lead | 当前空间布局规格、艺术方向及游戏内视觉复核 |
| Coder | 保持同一 `GameState`、工坊/园地双场景，调整 `App.tsx` / `workshop.css` / `experience.css` / Pixi 预览及输入；保留现有测试 ID/有效交互 |
| Painter、Technical Artist | 正式美术线当前仍暂停；未来由画师交完整效果图，再由技美自主拆件 |
| Reviewer | 独立审查代码和 CI |
| Experience QA | 实际浏览器检查布局、点击、拖放、反馈与两种分辨率 |

验收条件：

1. 工坊 **后景左设备球—中间约 30% 接客窗—右侧货架** 清楚可辨；球不是中央主视觉，前景柜台跨几乎全屏。
2. 剥壳机、榨汁装杯机、物品栏/仓储/元素存放与可拖放区域全在前景，操作不因风景遮挡而不可达。
3. 左侧水晶球在工坊内呈 **正确比例的圆形**，随真实开局、播种、幼苗、挂果、采摘与已开垦格更新缩略图，点击能进入园地；预览不复制世界物品。
4. 接客窗口接近 30% 屏宽，人物出现与离开都保持完整窗景；委托和对话操作可按需展开。
5. 默认引导不再固定占半条状态栏；错误反馈及重新打开帮助的入口均可用。
6. `1600×900` 桌面和 `1280×720` 模拟触摸实际截图与输入验证通过；园地原有播种/采摘/浇灌、工作台加工/交单、游戏日及存档逻辑无回归。

**本文件是美术与交互布局合同草案，未修改实际 UI 源码。** 真实界面与体验结论必须以 Coder/QA 的运行结果为准。
