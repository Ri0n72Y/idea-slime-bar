# Aquamelon Kitchen — 2D Lua 参赛合同 v3

> **范围**：千星奇域 2D 单机 Demo；游戏计算、唯一世界状态、UI 动态控制、颜色计算、提示词生成均由**本地 Lua**完成；编辑器布置静态 UI 和资源。不使用服务端节点图、多人同步、网络 AI、未来联机兼容层。
>
> **适用优先级**：本页对本次参赛版优先；旧 Web/正式千星设计依旧保留在 `mvp/aquamelon-kitchen/`，不得把这里的专用参数反写成其他平台的通用合同。这是设计，不是实机通过证明。

## P0 和 P1

- **P0**：放土/播种 → 主动生成与收集七元素球 → 生长、亲和遗传与富集 → 芽、叶、花、果 → 成熟反应 → 采摘 → **一颗成熟水瓜一键转换唯一一份果汁** → 中文 AI 品尝提示词完整交付玩家。
- **P1**：P0完成后，像素画对象替换、放大镜查看并在底部状态栏打印描述、手套点击采摘；P1不新增数值规则。
- 普通界面隐藏内部七维精确值；Debug可查看；品尝文本必须公开全部果汁事实数据。自然时间和Debug快进使用**同一个**Lua结算入口。

## 时间和生长数值

- 参赛 `1uh=现实10秒`；所有 V、Growth、概率时间用模型uh计，不能随帧率增加产量或随机机会。
- 元素顺序固定为 **Fire/Hydro/Anemo/Electro/Dendro/Cryo/Geo**；主动富集生成七选一等概率纯元素球，**初始固定50V**；半衰期0.25uh，余额 `50×0.5^(elapsedUH/0.25)`，小于1V销毁；按点击当刻实际余量收集。此50V仅限本参赛版，取代旧80V均值。
- 土壤七维总容量1000V、自然保留0.99/uh；超量结算时按七维比例缩放；`F_soil(S)=ln(1+S/200)/ln(6)` 为根系**唯一**共享土壤效率。
- `RootPreference=[.80,1,.85,.75,1,.70,.90]`；Tree基础Affinity `[.85,1.15,.90,.75,1.20,.70,.95]`；Leaf模板 `[.75,1.10,1,.85,1.30,.90,.80]`；花果模板均1；ExtraAffinity=1，父亲和偏移继承率0.5。RootPreference≠Affinity。
- 根系总速率上限：**Seed 2、Seedling 1.85、Sapling 16 V/uh**；单通道取用还受真实 Soil、RootPreference、`0.30×Tree BaseAffinity`基础上限约束，候选总额超共享 cap 则同比缩减。
- Sapling额外根系充盈限流：令 `R=ΣTreeReserve`，`F_root=1`（R≤100），`F_root=ln(1+(180−R)/80)/ln2`（100<R<180），`F_root=0`（R≥180）；此函数只限制根系，不替代 Growth Budget。
- Tree Reserve 容量180V；无休眠，预算基准 `B0=5.4V/uh`；`sig(x)=1/(1+exp(-x))`；`F_growth(R)=[sig((R−95)/12)−sig(−95/12)]/[sig((180−95)/12)−sig(−95/12)]`；不将七元素Affinity额外归一，逐元素实际扣Reserve不超过余额。
- 每片叶名义获得Tree当次预算30%，未消费量返回Tree；至多3叶。花苞/花/青果仅在**各自母叶所得预算**内继续取80%，不可从Tree重复扣；LargeLeaf自身Growth效率60%。
- 第一枚Bud在进入Sapling时立即生成；随后**每24uh**按模型日一次机会（原04:00检查点），1叶40%、2叶1%、3叶0%；不能按帧或每小Tick重复投签。固定50V后的实际产量仍须重新验算。

| 生长事件 | 阈值与重要账户边界 |
| --- | --- |
| Seed→Seedling | Tree Growth累计45G，**不断代** |
| Seedling→Sapling | 同一Tree Growth累计90G，逐维1G→1V初始化Reserve；Sapling树自身Growth清零且首Bud立即产生 |
| Sapling塑形 | 主干本轮Growth100G，仅更新亲和循环，不升另一级树 |
| Bud→SmallLeaf | Bud独立20G；掐芽时Bud已形成的Growth逐维返回Tree |
| SmallLeaf→LargeLeaf+FlowerBud | **本叶**26G时同步进行；只重置本叶阶段Growth，**无额外18G** |
| FlowerBud→Flower→GreenFruit→MatureFruit | 单一连续生殖物质量 `E_free[7]` 累计到 **12 / 40 / 90G**；形态切换不清零；开花和结果各固化一次Affinity |

- FlowerBud出生即开始可食七维物质账户；成熟前是 `E_free[7]`，成熟后为 `E_free[7]+Products[]`；`M=ΣE_free+ΣProducts.amount`。无第二份 `FruitElementAmount`。成熟**先锁阶段**再结算反应，物质量减少不能使阶段回退；采摘只转移账本、不复制。

## 成熟后自然富集：线性新规则

- 90G成熟后，**后续**生殖自然成长立即降到同等条件下成熟前速度的 **50%**；从90到150G随当前物质量线性降低，达到150G为0。
- 令成长输入前的 `M=ΣE_free+ΣProducts.amount`；`F_enrich(M)=0.5×clamp((150−M)/60,0,1)`。M为90/105/120/135/150G时倍率分别50/37.5/25/12.5/0%。
- **150G不是硬库存上限**：风扩散等反应可以改变M，不裁剪或销毁产物；若M降回150以下按当前值恢复自然富集资格。废弃旧20%固定比例、指数k和M_cap作为本参赛富集规则。

## 反应与形态身份

- 数值以 [果实反应 §6.18](../../mvp/aquamelon-kitchen/fruit-reaction-settlement-design.md) 为准：`1U=30G`；非风普通触发方严格>30G，目标需满足该方向完整配额；普通产物等于双方被消耗物质量，保持守恒。
- 风扩散仅作用于自由火/水/雷/冰，合法风>30G且目标至少15G；先于普通反应；目标真实消耗按0.5U量子，KQM源端及传播端各0.8税；不生成 `Products[Swirl]`，允许M净变化。同一Growth事件最多一次合并扩散，不重入。
- **R1已确认**：水雷感电首次必须满足**双方完整12G**首轮实际扣费且主动方严格>30G；水60雷10不启动，雷经后续合法生长达到12G时当事件立即启动。启动后每uh尾次可以不足12G。
- **R2已确认**：普通反应在**首次成熟或随后真实Growth事件内**只要满足合法条件就立即结算；余量仍足额时同事件允许继续合法反应，不得凭空等待下一uh，亦不得在无真实成长输入的空Tick重复扣旧库存。燃烧及感电后续周期与普通一次性事件分离。
- 草原核被火或雷进阶时按专用规则消耗全部原核；激元素受雷或草催化进阶时保持已有激元素不消耗；冻结为稳定产物不可扩散。
- **首次真实生成反应产物**的种类及反应方向，按本次真实结算顺序**锁定整颗果子的名称和完整图标**，以后即使生成其他产物、甚至第一产物进阶消耗至零，外观都不再换。首次产物只是**外观历史身份**，不是风味过滤器；所有**当前存在**的其它产物仍参与实际品尝，已被消费的历史产品不重复计味。风扩散无独立产物，单纯扩散不锁定外观。

## 七元素颜色：Lua 归一混合、无门槛

七元素主体色和文件名只采用 [七元素视觉参考](../visual/element-reference.md)：

| Fire | Hydro | Anemo | Electro | Dendro | Cryo | Geo |
| --- | --- | --- | --- | --- | --- | --- |
| `#D56C45` | `#4389CB` | `#339F84` | `#8742CE` | `#8EAF43` | `#68B8BF` | `#C2A045` |

- **无反应产物**：把本对象出生/当前阶段固化的 `BaseAffinity[7]` 七维总和归一得 `a_i`，底色 `C_base=Σa_i RGB_i`；真实当前Growth[7]（生殖期用 `E_free[7]`）归一为 `g_i`，`C_growth=Σg_i RGB_i`；显示 `C=0.7 C_base+0.3 C_growth`。Growth总和0时仅使用底色。
- **已有反应产物**：切换为首次产物专属**整颗果子**图标与名称；只将此刻尚未反应的 `E_free[7]` 归一混合色**以30%强度**叠加该图标，余量0则不叠色。已进入 Products 的元素不再重复作为自由色来源。
- **所有正量元素立即参与**，无主元素最大值选取、50%阈值或额外显色门槛。三个RGB通道线性加权并转换合法颜色，颜色不消耗资源。
- Lua负责计算、重绘及调图；编辑器提前导入图片/布置控件，Lua使用已注册 `imageSource/imageId`，不能直接把PNG路径当运行时ID。

## 七元素风味与所有产物

**参赛版采用七元素及其元素反应的感官合同，不采用旧三阶段27项Taste数值公式。** 入口/中段/回味可以作为AI叙述结构，但不要求生成没有真实映射依据的27项数字。

| 元素 | 已确认感官 |
| --- | --- |
| 水 | 清润、柔和、本味润泽 |
| 火 | 温暖至热灼，不必改变真实温度 |
| 风 | 释放和传播已有香气；纯风从舌尖扩散至口腔的萦绕感 |
| 雷 | 活跃、跳跃、爆裂刺激 |
| 草 | 生发、发展与丰盈 |
| 冰 | 平抑现有风味的起伏和释放，并非冰镇 |
| 岩 | 凝聚为胶冻/晶质等可咀嚼结构 |

- 蒸发/融化按**触发方向**区分：水→火清冽，火→水温灼，火→冰炽灼，冰→火凝味；不是直接按元素占比生成甜辣。
- 感电是持续细麻的气泡水意象（不需真实气泡）；超载是瞬间爆炸式强刺激；超导是绵密酥麻且使已有风味更易辨识。
- 岩结晶分别与水/火/冰/雷构成滑润/弹热/清脆/跃动的可食水晶胶冻。
- 原激化让既有鲜香潜力苏醒，超激化更活跃、蔓激化更绵长；绽放为柔嫩多汁的植物果粒，超绽放弹性咀嚼持续释放，烈绽放为一咬即破、风味集中前段的爆爆珠。
- 风扩散加强**已有**香气传播，不凭空引入固定香型。
- **冻结**直接作为**冰块**，有冰凉/冰质体验；这与未反应冰元素的风味平抑区分。
- **燃烧**是**草的生发被火激发，形成活跃、持续的热感**；不是超载那种瞬间爆炸热，也不自动给焦糊烟熏辣椒味。
- 果实首次反应产物仅锁**外形**；最终口感必须解释**全部当前存在**的自由元素与反应产物，已被消耗的旧反应产物不重复计入。

## 采摘、加工与玩家品尝

- **一颗熟水瓜 → 唯一一份水瓜汁**：采摘果实材料完整转移 `E_free[7]+Products[]`、Affinity及首次反应外形标记；一键加工后旧材料退出，果汁成为唯一承接账本的物品，不在参赛版额外产瓜壳或多份副产物。
- Lua `Taste` 只读实际汁快照生成**完整、自包含**的中文提示词：身份和外形、七个自由元素值含0值及单位、所有现存反应产物及数量、对应已确认风味解释、向量来源/含义、入口/中段/回味品尝请求。事实与AI想象严格分离，**不把旧27项数值冒充已计算风味向量**。
- 玩家可把提示词交给自己喜欢的外部对话智能体；游戏不调用外部AI。TextWindow完整阅读或可靠分页截图属于P0交付；未有实机确认的剪贴板API不得虚称一键复制可用。

## Lua/UI 最小已验约束与验收

- 已有千星编辑器最小试验支持 `script.object` 获取已挂载的客户端 UI 宿主、`FindChild` 获取已有控件、Lua更新文字和基础点击绑定；创作者控制静态布局，Lua不擅改位置尺寸锚点。
- 多模块 `require` 需在脚本资源管理器**逐文件映射**；完整多模块链路、图片换图/调色、长文本极限、触屏/剪贴板目前不能宣称已实机通过。
- `Game`持有唯一状态并结算，`UI`只做映射/领域动作，`Taste`仅读果汁；不引入ECS、通用物品框架、第二份权威向量或服务端依赖。
- 玩家普通屏幕显示合法Growth进度、可信速率及已批准颜色暗示，不泄漏七维分项；Debug可看完整数据；列表的可视槽绑定真实球/材料ID，不等于对象身份。
- 最少实机验证一次完整播种→成熟→反应→收获→汁→全文提示词，两种元素培养轨迹呈现可解释差异；检查50V球衰减、Growth断代、90/150线性、首次产物锁形、多产物品尝、冻结/燃烧区分、UI操作合法性、提示词可交付。

**尚待实现/校验**：固定50V下的产量与首果进度；分数uh数值稳定/预算返还；收获后复花Growth门槛（非首果P0前置）；千星图片ID与长文本/触摸真实设备能力。不要把这些校验事项说成已决定规则尚未决定。
