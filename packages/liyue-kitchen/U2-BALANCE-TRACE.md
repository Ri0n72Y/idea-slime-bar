# U2 可重放数值轨迹与验证边界

## 试玩参数与来源

- 领域纯函数源码：`src/domain/config.ts`、`growth.ts`、`reactions.ts`、`game.ts`。
- 七维顺序：`Fire / Hydro / Anemo / Electro / Dendro / Cryo / Geo`，完全独立的 Soil[7]、TreeReserve[7]、Tree/Bud/Leaf/Reproductive Growth 账户。
- 已确定合同：`1U=30G`；Soil 总 cap `1000V`、保留率 `0.99^Δuh`；每次凝聚一种元素 `50V`；球半衰期 `0.25uh`，低于 `1V` 消失；Reserve cap `180V`；根系及树的预算参数按源文档逐项落地。
- **候选，未定稿**：每个游戏日全洞天共享 `N=8` 次凝聚、显式夜间 `K=24uh`。这两个值都位于 `src/domain/config.ts`；单球50V不受 N 影响。Lead 需在真实游玩与独立数值复核后决定 N/K。
- 随机流采用持久化 xorshift32，初始种子 `0x17a5b7e1`，每日由凝聚元素身份及模型日 04:00 芽机会顺序消费。每次调用 `applyCommand` 和 `advancePlotOneUH` 都产生可重放的领域状态；白天不推进 `worldUH`。
- 轨迹：新游戏唯一种子播 P01；每天执行8次「凝聚→收集→向 P01 浇灌」，再请求并确认结束今日；每晚逐小时循环24次，晨间事件及投入账本记于 `lastNightReport`。不收获，不加工，不提前实施 U3+。

## 账本与测试

- 每晚 `NightReport` 保存逐格 Soil / Reserve / TreeGrowth 的前后七维快照、植株阶段、叶片与果实数量、关键事件（包括 `worldUH` 触发序列），和当夜 `soilEvaporatedV`、`rootAbsorbedV`、`reserveConsumedV`、Tree/Bud 自身 `1V→1G`、器官新G、LargeLeaf 40%环境逸散V、风扩散净变G、元素球衰减损失V。
- 土壤守恒（没有浇灌发生在夜间时）：`Soil_before - Soil_after = evaporatedV + absorbedV`。正常根系从 Soil 只扣一次、Sapling Reserve 使用只扣一次；Leaf/Fruit 的 G 产出记录其各自亲和与效率，不能直接与 V 相加声称「G 质量守恒」。
- MatureFruit 生殖账户唯一 `E_free[7]` 与 Products[]，12G/40G 只记录塑形快照；90G 成熟先锁定，再根据本次真实自然 Growth 检查合法反应；普通反应按30G触发方、严格超过30G门槛、方向及足额被动原料；持续反应按真实uh处理。反应的专项确定性测试见 `src/domain/game.test.ts`；这条随机轨迹可合法不产生任何反应，不能伪造一个「必定反应」样本。
- `node --experimental-strip-types --test src/domain/game.test.ts` 为本地领域验证；实际冻结安装、类型检查、Playwright 与截图必须以准确 PR HEAD 的 CI 日志为准。

## 实施限制

- 04:00 出芽机会以绝对模型小时判定，每24uh至多一次；没有每日额外赠送抽签。
- 固定1uh 积分粒度会造成与分数uh基准的积分差异；本切片必须由 Reviewer 核对边界，未来可提高到按模型事件拆分时间步。
- 本切片没有采摘、加工、订单、开垦和 Tauri。已成熟但未采摘的果仍按40%母叶预算与本果M的富集倍率继续成长。
